# 网关 API网关 产品简介

## API网关

API网关作为现代应用架构的核心组件，承担着统一管理API 和 AI 请求、协调系统间交互的关键角色。其核心价值在于通过标准化接口托管、服务集成与能力开放，构建稳定、高扩展的企业级服务中台。

**产品形态与能力**

云原生 API 网关深度融合API管理、流量控制及微服务治理能力，是高性能、高扩展性网关。 AI 网关面向 AI 场景全新打造，统一代理大模型 API 和 MCP Server，并提供丰富的集成和治理能力。

**解决方案与优势**

**基于开源，优于开源**

借助Spring Cloud Gateway构建接入层网关及API管理平台，基于大规模的落地经验，极大丰富了网关层流量管理能力，以应对复杂的生产场景。

**强大的系统架构兼容性**

既支持对接微服务架构下的注册中心（如Nacos、Eureka、K8s等），监听后端服务及快速发布；又支持协议转换（如WebService、gRPC、Dubbo等），可将不同协议的服务统一管理及发布，为系统间集成提供解决方案。

**生态开放**

提供能力开放平台，通过统一的管理和授权，将平台能力对外开放，与合作方进行能力及生态共建。

### 产品价值

API网关具有高性能、稳定可靠、轻量级、简便易用、跨协议开放互联以及一站式服务管理等特点。

**高性能稳定可靠**

稳定可靠地支持大规模请求，基于阿里巴巴内部长期使用与沉淀的高可用、高性能分布式集群技术产品构建。

**轻量级简便易用**

实现企业业务能力的高效数字化输出和迅捷变更。 API 发布、配置变更便捷灵活。 API 调用简单方便。 处理能力按需简便扩容。

**跨协议开放互联**

实现从简单的应用间调用，到新建与遗留系统之间，以及企业组织间的能力互通。 支持不同系统、协议服务安全可控的互联，对接企业原有系统和账号体系。 支持复杂结构参数转换，以及多种常用协议的服务 API 发布和消费。

**微服务集成**

可以对接 SpringCloud/Dubbo/HSF 等多种微服务后端应用。

**一站式服务管理**

整体把握控制跨平台、跨系统、跨企业组织的能力开放，实现能力的统一管理、组织和互动。 完整的 API 生命周期管理，服务目录，服务授权，用户管理。 角色化的服务发布者、消费者、管理者，以及灵活的权限管理。

**高度适配AI场景**

AI网关具备高并发架构、毫秒级无中断配置、WASM热插件与全场景插件生态，支持SSE流式协议及资源优化，实现AI服务的稳定性、扩展性与易用性。 企业级可靠性保障：基于高并发场景的坚实底座，可实现零中断的智能配置更新。 灵活扩展能力：覆盖全场景的插件生态，通过WASM沙箱实现热插件架构革新。 开箱即用的安全与易用性：标准化控制台与白屏化配置，具备高度自动化能力，可实现极简部署。 高效流式处理引擎：支持全链路流式协议，提升资源利用率，降低基础设施成本，并实现性能突破。 更多信息，请参见《**AI****网关****产品简介》** > **《产品价值》**。

### 应用场景

**经典应用服务暴露及流量管控**

**服务暴露及流量管控：**兼容 K8s Ingress 标准，支持微服务、函数服务等多种后端服务，支持 K8s、
Nacos 等多种发现方式，具备高集成、易使用、易扩展、热更新的特点。 容器及微服务的流量管理：作为容器服务的接入层，兼容 K8s Ingress 标准，提供精细化的路由或 API 管控。支持一键导入K8s SVC 或 Nacos 注册服务，请求直连 Pod IP，支持 Nginx Ingress 核心注解扩展，并提供限流、预热、灰度等服务治理能力。 多活容灾：用于多个集群的统一接入层，进而实现容灾多活等功能。支持 ACK、MSE Nacos，FC，DNS 域名，IP 固定地址等多种服务来源，可按比例/请求内容精准路由，支持健康检测， 服务 fallback。

**API 全生命周期管理**

**API** **全生命周期管理：**提供 API 设计、开发、发布及下线的全生命周期管理能力，并支持多环境管理，帮助
团队更高效、安全地管理和发布 API，推动业务的快速迭代和创新。 开发规范化，效率提升：通过 API 全生命周期管理，开发者可以基于 API First 的模式实现前后端的并行开发，实现系统的快速迭代。 API 精细化管理：在上下游合作伙伴开放、内外部系统接入及协作的使用场景下，实现 API 的精细化管理，避免开放范围的失控。 多环境管理：通过多环境管理，开发、测试、预生产和生产环境可以相互独立，避免在开发和测试过程中对生产环境造成影响，同时也便于进行不同阶段的测试和验证。

### 使用限制

API网关对某些具体指标进行了约束，您在使用API网关时注意不要超过相应的限制值，以免系统出现异常。

| 限制项 | 限制值 | 说明 |
|---|---|---|
| API/路由数量 | 10000 | API/路由数量超过该值可能会导致网关转发出现异常，需评估网关容量。 |
| 并发数 | 1000 | 单节点超过 1000 并发需要单独评估后端服务的 RT 和请求并发数，避免引起网关内存溢出。 |
| 请求体大小 | 4MB | 网关可动态调整请求体大小，但超过默认值的请求体在高并发情况下会导致网关 OOM，建议配置时注意网关容量。 |
| 文件传输 | 不建议传输文件 | 同请求体大小，文件传输是导致网关 OOM 的最常见原因，建议文件传输经过文件服务进行，仅通过网关传输文件 URL。 |
| 超时时间 | 10秒 | 网关可动态调整请求超时时间，但超过默认超时时间容易导致网关出现 OOM。 |

### 基本概念

本文主要对API网关涉及的专有名词及术语进行定义和解析，方便您更好地理解相关概念并使用API网关。

**网关实例**

API网关通过实例化的架构来支持流量的调度。通常推荐一个ACK集群配置一个网关，也支持通过 namespace进行同集群的多实例隔离。主要分为直接处理业务流量的数据面（gateway）和负责管理配置的控制面（controller）。

**路由**

定义“什么样的请求”应该被转发到“哪个服务”的规则。网关可根据请求内容（如域名、路径、Header 等），将流量按比例或按条件精准地路由到不同的后端服务乃至不同的集群。

**服务**

对后端业务应用的逻辑抽象，代表了一组能够处理请求的具体工作负载。可以是模型服务、Rest服务、数据库服务。

**域名**

客户端访问后端服务的公开入口地址，也是网关进行流量匹配和策略执行的起点。

**插件/策略**

网关提供了插件市场，内置认证鉴权、流量管控、安全防护等多种功能扩展插件，可以对网关进行灵活、 个性化的能力扩展。

**消费者**

网关通过消费者来为路由开启认证能力。
