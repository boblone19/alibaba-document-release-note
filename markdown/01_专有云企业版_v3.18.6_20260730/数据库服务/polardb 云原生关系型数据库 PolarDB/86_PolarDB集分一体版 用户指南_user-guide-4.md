### 实例变配

一个PolarDB-X实例是由多个节点组成的分布式集群。单个节点承担了SQL路由、数据合并、聚合等功能。 通过实例变配，您可以变更实例的节点规格，在业务繁忙时进行升配，承载更多的业务流量QPS，在业务空闲时进行降配，避免资源浪费。

**注意事项**

降配过程中由于应用与实例连接会中断，可能在短时间内会产生闪断，请确保应用程序具备重连机制。

**操作步骤**

1. 登录PolarDB集分一体版控制台。

**说明**

控制台支持以下功能： ：单击可刷新实例列表信息。 ：单击可选择采用**默认**或者**紧凑**模式显示实例列表。 ：单击可选择实例列表中显示的实例属性。 ：单击可将实例列表信息导出到本地。 云原生数据库理
2. 在目标实例右侧的**操作**栏中，单击**变配**。

**说明**

您也可以单击目标实例ID进入**基本信息**页面，在**配置信息**区域右上角，单击**变配**。
3. 在**变配**页面，选择目标节点规格、存储空间、共享类型和变配时间等。

**说明**

变配完成后，计算层和存储的节点都会升配或降配到相同的目标节点规格。 变配时间支持选择**立即变配**或**运维时间变配**。运维时间设置请参见设置可维护时间段。
4. 单击**提交**，完成变配。

### 单个数据节点灰度升级

支持对PolarDB 集分一体版企业版实例中的单个数据节点进行独立内核升级。通过灰度升级，确保在升级过程中业务的高可用性与数据安全性，实现平滑过渡。

**前提条件**

实例必须处于“运行中”状态，且无其他正在进行的运维任务（如扩容、变配）。 仅支持企业版（分布式）。 目标数据节点下的所有副本（主、备、日志）状态必须健康，无延迟报警。

**名词解释**

| 名词 | 解释 |
|---|---|
| DN | 数据节点（负责存储实际数据的单元）。 |
| Leader | 主副本（处理读写请求的核心副本）。 |
| Follower | 备副本（同步主副本数据，用于容灾或只读）。 |
| Logger | 日志副本（专门负责记录日志，保障数据一致性）。 |

**操作步骤**

**步骤一：执行单副本灰度升级**

1. 登录PolarDB集分一体版控制台。

### 数据投版快速回滚

数据投版快速回滚是PolarDB 集分一体版标准版提供的一项数据保护能力，用于在业务验证（如DDL变更、数据写入等）后，快速将数据回退到验证前的状态。

副本）节点之间的数据同步，使follower节点保留验证前的数据快照。
**恢复副本同步**：业务验证正常后，恢复follower与leader之间的同步，实例恢复正常运行。

### 自定义地址

PolarDB 集分一体版为您提供自定义连接地址功能，可以帮助您定制化的分配业务流量到指定的计算节点集合。

**使用限制**

仅支持在PolarDB 集分一体版企业版实例中创建自定义连接地址。

**注意事项**

自定义连接地址中至少需要含有2个计算节点。

**优势**

一般情况PolarDB 集分一体版实例会有2个及以上的计算节点，并且内网地址挂载的计算节点数量是不可修改的，这种情况下您将不能定制化地为不同的业务流量分配合适数量的计算节点。为了满足您对业务流量更多的定制化需求，PolarDB 集分一体版推出自定义连接地址功能，其有如下优势： 业务流量的物理隔离：可以让不同业务使用不同的自定义连接地址，且这些自定义连接地址所挂载的计算节点不重合，以实现业务流量的物理隔离。 减小跨机房访问的网络延迟：PolarDB 集分一体版的多可用区实例，在主备可用区各有一组计算节点， 您可以分别基于主备可用区中创建不同的自定义连接地址，再分别提供给部署在主备可用区的应用APP使用，以达到就近访问计算节点的目的，减小跨机房访问的网络延迟。

### 变更配置

一个PolarDB-X实例是由多个节点组成的分布式集群。单个节点承担了SQL路由、数据合并、聚合等功能。 通过实例变配，您可以变更实例的节点规格，在业务繁忙时进行升配，承载更多的业务流量QPS，在业务空闲时进行降配，避免资源浪费。

**注意事项**

数据节点变更配置后，PolarDB-X 实例数据节点的规格不一致，实例操作方式将发生如下变化： 数据节点变更配置后，PolarDB-X实例将无法对实例整体升降配，需要对计算节点和数据节点单独变配。 数据节点变更配置后，PolarDB-X实例将无法通过修改数据节点数量的方式进行缩容，请在数据节点管理页面删除指定数据节点的方式进行缩容。

### 设置SSL加密

为了提高链路安全性，您可以启用SSL（Secure Sockets Layer）加密，并安装SSL CA证书到需要的应用服务。SSL在传输层对网络连接进行加密，能提升通信数据的安全性和完整性，但会同时增加网络连接响应时间。

**注意事项**

SSL的证书有效期为1年，请及时更新证书有效期并重新下载配置CA证书，否则使用加密连接的客户端程序将无法正常连接。 由于SSL加密的实现原理，启用SSL加密会显著增加CPU使用率，建议您仅在外网链路有加密需求的时候启用SSL加密。内网链路相对较安全，一般无需对链路加密。 开启或关闭SSL加密会重启实例，请谨慎操作。

### 三权分立

#### 功能介绍

PolarDB-X新增三权分立模式，您可以将高权限账号拥有的权限分给系统管理员、安全管理员和审计管理员这3个角色，避免因权限高度集中带来的风险，增强数据库的安全性。

**风险与解决方案**

云原生数据库安全

**风险**

传统数据库运维模式下，数据库管理员DBA（Database Administrator）拥有的权限过高且集中，容易在某些场景下给业务带来风险： DBA误判导致系统安全事故。 DBA出于某种目的进行非法操作。 DBA、第三方外包人员或程序开发人员越权访问敏感信息。

**解决方案**

PolarDB-X新增支持三权分立模式，打破传统数据库运维由DBA行使特权的独立控制体系，使得数据库管理员DBA、安全管理员DSA（Department Security Administrator）和审计管理员DAA（Data Audit Administrator）3者的权责更加清晰。其中： 数据库管理员（DBA）：只具备DDL（Data Definition Language）权限。 安全管理员（DSA）：只具备管理角色（Role）或用户（User）以及为其他账号授予权限的权限。 审计管理员（DAA）：只具备查看审计日志的权限。

### Native Flashback

Native Flashback功能可以通过SQL语句查询或恢复指定时间点的数据，保证在误操作后可以快速获取历史数据。在数据库运维中，误更新或误删除数据等操作可能导致业务中断。传统的恢复方法，如使用Binlog 或备份集，过程复杂且耗时较长。PolarDB 集分一体版提供Native Flashback功能，您仅需通过简单的 SQL语句，即可查询指定时间点的历史数据或将数据快速恢复到误操作发生前的状态，从而最大程度地减少业务损失。

**功能说明**

Native Flashback是PolarDB 集分一体版基于InnoDB引擎实现的一项功能。它通过保留特定时间范围内的undo日志，使您能够查询这些历史版本的数据。当发生数据误操作时，您无需进行复杂的操作，即可利用 `AS OF` 语法快速查询历史数据，并根据需要将其恢复，实现秒级数据闪回。

**适用范围**

实例版本：PolarDB 集分一体版引擎版本：8.0

**注意事项**

过 `innodb_undo_space_supremum_size` 参数进行配置。 Native Flashback功能的查询结果为最接近指定时间点的数据快照，不保证与指定时间点的数据完全一致。 暂不支持跨DDL操作的历史版本数据查询和恢复。例如，您无法通过Native Flashback查询某个已经被删除的表的内容。

**语法说明**

Native Flashback提供了全新的AS OF语法，通过该语法指定需要回滚的时间。语法规则如下：

```
 SELECT ... FROM <表名> AS OF TIMESTAMP <表达式>;
```

其中，在表达式中指定回滚的时间，该表达式支持多种形式，示例：

```
SELECT ... FROM tablename AS OF TIMESTAMP '2020-11-11 00:00:00'; SELECT ... FROM tablename AS OF TIMESTAMP now(); SELECT ... FROM tablename AS OF TIMESTAMP (SELECT now()); SELECT ... FROM tablename AS OF TIMESTAMP DATE_SUB(now(), INTERVAL 1 minute);
```

**重要**

若您的业务场景需要申请创建并使用IPv6实例，必须确保当前租户组织已显式授予数据库产品访问SLB 服务的权限。若未完成此授权操作，则无法成功创建IPv6实例。

2. 在页面顶部的菜单栏中，单击**配置**。
3. 在左侧导航栏，单击**RAM****服务角色**。
4. 在RAM服务角色页面，单击左上角**创建****RAM****服务角色**。
**服务名称**选择**负载均衡****SLB**，**授权组织名称**选择需要授权的组织即可。
5. 单击**确定**，完成授权。
