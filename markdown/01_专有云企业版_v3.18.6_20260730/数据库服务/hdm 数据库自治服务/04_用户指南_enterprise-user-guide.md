**前提条件**

登录Apsara Uni-manager运营控制台前，确认您已从部署人员处获取Apsara Uni-manager运营控制台的服务域名地址。 推荐使用Chrome浏览器。

**操作步骤**

1. 在浏览器地址栏中，输入Apsara Uni-manager运营控制台的服务域名地址，按回车键。

**说明**

单击页面右上角的当前语言可以切换其它语言。 授权登录是第三方认证中配置了全局IdP设置才会显示，且“授权登录”名称用户可按需自定义。 由于浏览器证书过期或环境开启HTTPS认证等出现多次单击继续访问或无Apsara Unimanager运营控制台地址入口等现象，此时需要安装证书才能正常访问。单击页面右上角的**浏览器证书安装**，可打开浏览器证书安装指南。
2. 输入正确的用户名及密码。
制台

**说明**

请向运营管理员获取登录控制台的用户名和密码。 首次登录Apsara Uni-manager运营控制台时，需要修改登录用户名的密码，请按照提示完成密码修改。为提高安全性，密码长度必须为10~32位，且包含英文字母大小写、阿拉伯数字和特殊符号（感叹号（!）、at（@）、井号（#）、美元符号（$）、百分号（%）等）。

## 实例监控

### 快速入门

实例监控页面展示已接入数据库自治服务DAS的所有数据库实例列表，帮助用户快速了解各实例的运行状态和基本信息。

**前提条件**

已授权DAS获取云产品实例的监控数据。

**使用限制**

实例监控仅支持**阿里云云产品数据库实例**，不支持自建Redis等专有云外资源。 QPS和活跃会话数据**仅在实例完成授权后显示**。

**查看实例列表**

1. 登录数据库自治服务DAS控制台。

**实例基础信息概览**

| 模块 | 指标项 | 说明与运维建议 |
|---|---|---|
| Serve r信息 | 版本/运行时间 | 显示数据库内核版本（如 8.0.36 ）及实例累计运行时间（Uptime）。用于确认环境一致性及实例稳定性。 |

| Buffer Pool | 总页数/空闲页比例/ 脏页比例 | 展示InnoDB缓冲池状态。 空闲页比例：反映内存剩余空间。 脏页比例：反映待刷盘数据量。比例过高可能影响刷盘效率，导致IO抖动。 |

**吞吐量、负载与深层引擎指标**

| 分类 | 指标名称 | 详细说明 | 运维分析与建议 |
|---|---|---|---|

| 吞吐量 | QPS \| TPS | QPS：平均每秒SQL语句执行次数。 TPS：平均每秒事务数。 | 趋势分析：突增通常对应业务高峰。 异常排查：若QPS/TPS下降但CPU升高，通常存在锁等待或慢SQL阻塞。 |
|---|---|---|---|
| DML分布 | DML执行次数 | select：SELECT语句每秒执行次数。 insert：INSERT语句每秒执行次数。 update：UPDATE语句每秒执行次数。 delete：DELETE语句每秒执行次数。 | 业务画像：识别业务是读多写少还是写多读少，辅助制定索引优化策略（如读写分离架构调整）。 |
| 连接会话 | 连接数 | 活跃连接数：已打开连接中处于活跃状态的数量。 总连接数：已打开连接的总数量。 | 瓶颈定位：关注活跃连接数的波峰。若活跃连接数长时间维持高位，需检查是否有长事务或未释放的应用连接。 |
| 缓存效率 | InnoDB缓存 | 缓存命中率：从内存读取数据的比例。 缓存使用率：Buffer Pool的占用比例。 | 性能关键：命中率应接近100%。低命中率意味着大量请求穿透到磁盘（物理读），导致性能急剧下降。需考虑增大Buffer Pool或优化 SQL。 |
| 数据访问 | InnoDB访问行数 | rows read：每秒读取的InnoDB _ 行数。 rows inserted：每秒插入的 _ InnoDB行数。 rows updated：每秒更新的 _ InnoDB行数。 rows deleted：每秒删除的 _ InnoDB行数。 | 索引优化：若 rows read 极高但返回结果 _ 集很小，说明存在全表扫描，急需添加合适索引。 |
| IO读写 | 逻辑读/物理读 | 逻辑读：每秒逻辑读次数（从 Buffer Pool读取）。 物理读：每秒物理读次数（从磁盘读取）。 | IO瓶颈：物理读激增是性能杀手，通常由冷数据访问、Buffer Pool不足或缺少索引引起。 |
| 锁竞争 | 行锁平均锁定时间 | 单位通常为毫秒（ms），反映获取锁的平均耗时。 | 并发冲突：数值越高，说明事务间争用越激烈，可能导致应用端超时报错。 |
| 锁等待 | InnoDB行锁等待 | InnoDB行锁平均等待次数：统计周期内行锁平均等待次数。 InnoDB行锁当前等待次数：当前时刻正在等待行锁的次数。 | 阻塞源头：若此曲线不为0，说明存在阻塞。需结合“会话管理”功能查找阻塞源头（Blocker） 并终止异常会话。 |

| 临时资源 | 临时表、文件 | 临时表：创建临时表的数量。 临时文件：创建临时文件的数量。 | SQL优化：频繁创建磁盘临时文件会严重拖慢 SQL速度。通常是因为 sort buffer size 不足或缺少索引导 _ _ 致无法利用索引排序。 |
|---|---|---|---|
| 异常监控 | 慢查询 | 慢查询：两个相邻采集点间新增的慢查询数量差值（即该时间段内的慢查询增量）。 | 根因关联：慢查询突增往往是CPU飙升、响应变慢的直接原因。需立即抓取慢日志进行分析。 |
| 网络带宽 | 网络流量 | 总流量/流入流量/流出流量。 | 带宽限制：若流出流量打满实例带宽，会导致连接超时或丢包；若流入流量异常，需排查大字段写入或潜在攻击。 |

### 空间碎片自动回收

空间碎片自动回收是数据库自治服务DAS进行空间自动优化的一种方式，开启该功能后，主实例会自动执行 Optimize Table命令来回收表空间碎片，帮助您整理物理空间碎片。

**前提条件**

已购买并开通DAS自治版。 实例类型为RDS MySQL高可用版，且实例已成功创建14天或以上。 CPU规格不小于4核。 物理表必须是InnoDB引擎。

**优化前的检查项**

为了保证在执行**空间碎片自动回收**操作时，减少对数据库性能和空间的影响，会进行如下检查： 剩余可用空间至少是需回收表的物理空间的3倍。

**说明**

例如：需回收的表Table_1，该表的物理空间为30 GB，那么需要有90 GB的剩余可用空间，才可启动**自动空间碎片回收**。 表上无fulltext索引。 如下检测项如有一项或者多项未通过，会等待1至5分钟，再次检查，直至运维窗口期结束。 目标实例上没有备份任务。 没有正在执行的表结构变更操作。 查看实例的CPU使用率，预估**空间碎片自动回收**需花费的时间，确保前一天和上周同一时间段的CPU使用率低于70%，且执行前的CPU使用率低于80%。

**说明**

例如：表的物理空间为90 GB，预计空间碎片回收需花费30分钟，并且计划2021年12月10号凌晨3点执行，那么需确认如下3点： 2021-12-9 03:00至03:30的CPU使用率需小于70%。 2021-12-3 03:00至03:30的CPU使用率需小于70%。 在执行前检测2021-12-9 03:00开始的CPU使用率需小于80%。 需碎片回收的表上，没有执行时间超过3秒的SQL。 无悬挂事务（持有锁但是超过15秒未提交的事务）。 活跃会话数小于64。

**操作步骤**

1. 登录数据库实例控制台管理DAS。
2. 切换页签至目标数据库类型下，单击目标实例ID，进入实例详情页面。
3. 进入**自治功能管理**页面。
在左侧导航栏中，选择**自治服务**> **一键诊断**。单击**自治中心**，在**自治中心**页，单击**自治功能开关**。 在左侧导航栏中，选择**自治服务**> **性能趋势**。在**性能趋势**页，单击**自治功能开关**。
4. 在弹出的**设置**对话框中，打开**开启自治服务**开关。
5. 打开**空间碎片自动回收**开关，并配置以下参数。

| 参数 | 说明 |
|---|---|
| 表空间 | 物理表空间，默认值和最小值均为10 GB，最大值为100 GB。 说明单表空间过大会导致回收时间长，请根据实际业务情况选择合适的数值。 |
| 碎片率 | 物理表的碎片率，默认值和最小值均为20%，最大值为99%。 说明碎片率过大会降低空间优化频率，请根据实际业务情况选择合适的数值。 |

6. 单击**确定**。

### 锁分析

当数据库出现死锁、事务阻塞或元数据锁（MDL）等待等问题时，可借助DAS提供的锁分析功能，对锁等待关系进行可视化诊断，快速定位阻塞源头与依赖链路，有效提升问题排查效率，保障数据库服务的稳定性与高可用性。

**功能简介**

锁分析功能支持对数据库实例进行多维度的死锁分析、事务阻塞分析、元数据锁等待分析。
**最近死锁分析**：DAS基于 `SHOW ENGINE INNODB STATUS` 返回的最近一次死锁日志进行分析。如果发生

例当前会话中的元数据锁和事务阻塞情况。 元数据锁分析：DAS根据 `information_schema.processlist` 等的数据，推导锁等待关系，并生成相应的关系图。

AI助手将以流式方式实时展示推理过程，包括思考过程、工具调用和最终分析结论。可基于诊断结果进行后续的多轮对话，进一步深入分析问题。

**使用限制**

AI助手当前为只读模式，不会对数据库执行任何修改操作。 部分诊断场景需要选择具体实例后才能使用。 单实例巡检报告的生成耗时约1~3分钟，期间会以进度方式实时反馈。

**使用场景模板快速提问**

场景模板是AI助手预置的常用诊断场景，单击即可快速发起对应的诊断流程。
1. 在AI助手页面的输入框下方，单击**场景模板**。
2. 在弹出的场景列表中，可通过顶部的分类标签筛选场景：
**全部**：展示所有可用场景。
**会话与锁**：异常会话、死锁、锁分析相关场景。
**安全审计**：权限审计、安全配置检查相关场景。
**实例运维**：巡检报告、HA分析、错误日志相关场景。
**性能诊断**：CPU诊断、内存诊断、性能指标相关场景。
**知识检索**：数据库知识库问答场景。
3. 也可通过**全部引擎**下拉菜单，按数据库引擎筛选可用的诊断场景。
4. 单击目标场景卡片，系统将自动填入对应的提问模板并发起诊断。

**常见问题**

**Q1：AI助手可以修改数据库配置或执行SQL吗？**

A1：不会。AI助手当前为只读模式，仅提供分析与建议，不会对数据库执行任何修改、删除等变更操作。所有优化建议均需手动确认后执行。

**Q2：不同引擎看到的诊断场景为什么不同？**

A2：不同数据库引擎支持的功能有所不同，AI助手会根据所选引擎自动展示该引擎支持的诊断场景。具体支持的场景请参见上文“支持的诊断场景”表格。

**Q3：AI助手的诊断结果准确吗？**

A3：AI助手基于大模型技术和数据库运维经验知识库进行分析，诊断结果仅供参考。建议结合实际情况进行判断，必要时联系阿里云技术支持获取进一步帮助。

## 智能运维日报

智能运维日报是DBExpert Agent提供的自动化运维巡检功能。系统每日凌晨自动扫描所有纳管的数据库实例，识别潜在风险并生成运维报告，便于全面掌握数据库健康状态。

**开通说明**

AI助手和智能运维日报属于增值服务，需联系阿里云技术支持开通。开通后，控制台左侧导航栏将显示**AI**助

**功能概述**

自动巡检：每日凌晨自动运行后台任务，扫描所有接入实例的风险项。 优先级判定：根据问题严重程度将实例标记为紧急、高优先级、中优先级或正常，帮助您聚焦关键问题。 实例级报告：为每个实例生成独立的运维报告，包含关键指标趋势、重点问题、慢SQL分析、变更记录等内容。

**注意事项**

运维报告中的问题和建议需要您手动确认后执行，系统不会自动执行任何变更操作。

**查看运维日报总览**

**前提条件**

目标数据库实例已在实例监控页面完成授权。

**操作步骤**

1. 登录数据库自治服务DAS控制台。
2. 在左侧导航栏，单击**智能运维日报**。
3. 在页面顶部的引擎标签中，选择需要查看的数据库类型。
4. 通过页面右上角的日期选择器切换查看日期，默认为当天。
5. 查看页面顶部的指标卡片：

| 指标 | 说明 |
|---|---|
| 纳管实例 | 已生成运维报告的实例总数。 |
| 紧急 | 存在严重安全或稳定性风险，需立即处理的实例数。 |
| 高优先级 | 存在较高风险，建议24小时内处理的实例数。 |
| 中优先级 | 存在优化空间，建议本周内处理的实例数。 |
| 正常 | 运行健康、无需特别关注的实例数。 |

6. 查看**优先级分布**图表，了解各优先级实例的占比情况。
7. 查看**问题类型分布**图表，了解问题在各维度的分布情况。问题类型包括：
性能瓶颈 SQL性能锁与事务空间存储安全合规稳定性配置风险

**查看实例级运维报告**

1. 在运维日报页面的**实例列表**区域，查看各实例的运维概要。实例列表展示以下信息：
可以通过单击优先级标签筛选特定优先级的实例，或单击**展开全部**查看所有实例。

| 列名 | 说明 |
|---|---|
| 实例 | 数据库实例ID和名称。 |
| 引擎 | 数据库引擎类型。 |

| 优先级 | 该实例的运维优先级（紧急/高优先级/中优先级/正常）。 |
|---|---|
