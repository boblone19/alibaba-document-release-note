## 什么是PolarDB PostgreSQL版

**（兼容Oracle）**

本文档介绍云原生数据库PolarDB PostgreSQL版（兼容Oracle）。 PolarDB PostgreSQL版（兼容Oracle）是稳定、安全且可扩展的企业级云原生关系型数据库，基于开源数据库PostgreSQL，并在性能、应用方案和兼容性等方面进行了增强，提供直接运行Oracle应用的能力。您可以在PolarDB上稳定地运行各种企业应用，同时得到更高性价比的服务。 PolarDB PostgreSQL版（兼容Oracle）支持X86、ARM多集群混部，支持海光+Intel集群内混部，集成了账号管理、资源监控、备份恢复和安全控制等功能，并将持续地更新完善。

## 实例规格

实例有不同的系列、版本、规格，性能也有区别，本文介绍PolarDB的实例规格。

**通用规格与独享规格对比**

| 规格类型 | 特点 | 适用场景 |
|---|---|---|
| 独享规格 | 每个独享规格的集群独占所分配到的计算资源 （如CPU）。 不会与同一服务器上的其他集群共享计算资源，性能更加稳定可靠。 | 对性能稳定性要求高，以数据库为核心系统的业务场景，如金融、电商、政务和大中型互联网业务等。 |
| 共享规格 | 同一服务器上的不同集群，会互相充分利用彼此空闲的计算资源（如CPU）。 通过复用计算资源享受规模红利，性价比更高。 | 有降低成本诉求，追求高性价比的应用场景。 |
| 独占物理机型 | 完全独占一台物理机的所有资源，是独享型规格的顶配形态。 | 提供最高的性能稳定性和隔离性。以数据库为核心系统的业务场景。例如金融、电商、政务、大中型互联网业务等。 |

### 设置IP白名单

创建RDS实例后，您需要设置RDS实例的白名单，以允许外部设备访问该RDS实例。

**背景信息**

白名单可以让RDS实例得到高级别的访问安全保护，建议您定期维护白名单。设置白名单不会影响RDS实例的正常运行。 设置白名单包括两种操作： 默认的白名单只包含默认IP地址127.0.0.1，表示不允许任何设备访问该RDS实例。

**说明**

设置ECS安全组：添加ECS安全组，允许ECS安全组内的ECS实例访问该RDS实例。

**操作步骤**

1. 登录云数据库RDS控制台。
2. 在**实例列表**页面，定位到目标实例。
3. 单击目标实例ID或者单击实例右侧的**管理**，打开**基本信息**页面。
4. 单击左侧导航栏的**数据安全性**。
5. 在**白名单设置**页签中，单击**default**分组右侧的**修改**。
您也可以单击页面右侧的**添加白名单分组**新建自定义分组。

**说明**

6. 在**修改白名单分组**对话框中，填写需要访问该实例的IP地址或IP段，然后单击**确定**。详细规则如下：
若填写IP段，如10.10.10.0/24，则表示10.10.10.X的IP地址都可以访问该RDS实例。 若您需要添加多个IP地址或IP段，请用英文逗号隔开（逗号前后都不能有空格），例如 192.168.0.1,172.16.213.9。 单击**加载****ECS****内网****IP**后，将显示您当前阿里云账号下所有ECS实例的IP地址，可快速添加ECS内网IP地址到白名单中。

### 设置可维护时间段

**说明**

时间段为北京时间。 在进行正式维护前，RDS会给阿里云账号中设置的联系人发送短信和邮件，请注意查收。 实例维护当天，为保障整个维护过程的稳定性，实例会在可维护时间段之前进入实例维护中的状态。当实例处于该状态时，对数据库的访问以及查询类操作（如性能监控）不会受到任何影响，但除了账号管理、数据库管理和IP白名单设置外的变更操作（如升降级、重启等）均暂时无法使用。 在可维护时间段内，实例会发生1到2次连接闪断，请确保应用程序具有重连机制。

### 只读实例

#### 概述

RDS PolarDB实例支持添加只读实例，在对数据库有大量读请求和少量写请求时，只读实例用于分担主实例的数据库压力。本文主要介绍只读实例的功能特点以及功能限制。 为了实现读取能力的弹性扩展，分担数据库压力，您可以在某个地域中创建一个或多个只读实例，利用只读实例满足大量的数据库读取需求，以此增加应用的吞吐量。 只读实例为单个物理节点的架构（没有备节点），通过实例的复制机制能自动将主实例的更改同步到所有只读实例。只读实例必须跟主实例在同一地域，但可以在不同的可用区。只读实例拓扑图如下所示。 只读实例有如下功能特点： 规格可以与主实例不一致，并可以随时更改规格（没有时间限制），便于弹性升降级。 不需要维护帐号与数据库，全部通过主实例同步。 独立的白名单配置。 提供系统性能监控。 提供优化建议：RDS提供多种优化建议。例如存储引擎检查、主键检查、大表检查、索引偏多、缺失索引等。用户可以根据优化建议并结合自身的应用来对数据库进行优化。

### 标签

在实例数量较多的情况下，您可以创建多个标签，为实例绑定不同的标签对其进行分类，之后通过标签进行实例筛选。本文介绍标签的使用。

**注意事项**

标签由一对键值组成，键在同账号同地域下唯一，值无此限制。 每个实例最多可绑定20个标签。 标签从一个实例解绑后，如果没有绑定到其他资源，则该标签自动被删除。

**绑定标签**

1. 登录云数据库RDS控制台。
2. 在**实例列表**页面，单击目标实例**标签**栏
按钮。
3. 在**编辑标签**对话框，输入标签键和标签值后单击**确定**。

**根据标签筛选集群**

1. 登录云数据库RDS控制台。
2. 在**实例列表**页面，单击**高级筛选**按钮。
3. 您可以通过**实例****ID/****名称**、**VIP**和**标签筛选**过滤您的实例。在**标签筛选**的下拉框中选择目标标签。
4. 选择标签后，实例列表将显示所有绑定该标签的实例。

**查看集群绑定的标签**

1. 登录云数据库RDS控制台。
2. 在**实例列表**页面，当实例绑定标签数量较少时，将在标签栏直接显示对应标签，如绑定标签数量较多可移
动鼠标至目标实例**标签**栏图标上，查看目标实例绑定的全部标签。

**解绑标签**

1. 登录云数据库RDS控制台。
2. 在**实例列表**页面，单击目标实例**标签**栏
按钮。
3. 在**编辑标签**对话框，单击目标标签右侧
按钮，单击**确定**。

### 临时混访方案（同时保留经典网络和专

**有网络地址）**

为满足日益增多的网络迁移需求，RDS新增了网络混访功能，可实现在无访问中断的情况下将经典网络平滑迁移到VPC上。

**前提条件**

实例的网络类型是经典网络。 实例所在可用区已有可用的VPC和交换机。

**背景信息**

以往将RDS实例从经典网络迁移到VPC时，经典网络的内网地址会变为VPC的内网地址（连接字符串没有变化，背后的IP地址有变化），会造成1次30秒内的闪断，而且经典网络中的ECS将不能再通过内网访问该 RDS实例，为了能够平滑迁移网络，RDS新增了网络混访功能。 混访是指RDS实例可以同时被经典网络和专有网络中的ECS访问。在混访期间，RDS实例会保留原经典网络的内网地址并新增一个VPC下的内网地址，迁移网络时不会出现闪断。 基于安全性及性能的考虑，我们推荐您仅使用VPC，因此混访期有一定的期限，原经典网络的内网地址在保留时间到期后会被自动释放，应用将无法通过经典网络的内网地址访问数据库。为避免对业务造成影响，您需要在混访期中将VPC下的内网地址配置到您所有的应用中，以实现平滑的网络迁移。 例如，某一公司要将经典网络迁移至VPC时，若选用混访的迁移方式，在混访期内，一部分应用通过VPC访问数据库，一部分应用仍通过原经典网络的内网地址访问数据库，等所有应用都可以通过VPC访问数据库时，就可以将原经典网络的内网地址释放掉，如下图所示。

**功能限制**

在混访期间，有如下功能限制： 不支持切换成经典网络。 不支持迁移可用区。

**从经典网络切换至VPC**

在混访期间，您可以根据需求随时调整保留原经典网络的时间，过期时间会从变更日期重新开始计时。例如，原经典网络的内网地址会在2017年8月18日过期，但您在2017年8月15日将过期时间变更为“14天后”，则原经典网络的内网地址将会在2017年8月29日被释放。 修改过期时间的操作步骤如下所示：

## 账号管理

### 创建账号

要使用云数据库RDS，您需要在实例中创建账号。本文介绍如何为PolarDB实例创建账号。

**账号类型**

PolarDB实例支持两种数据库账号：高权限账号和普通账号。详细说明如下。

| 账号类型 | 说明 |
|---|---|
| 高权限账号 | 只能通过控制台或API创建和管理。 可以创建多个高权限账号，管理所有普通账号和数据库。 开放了更多权限，可满足个性化和精细化的权限管理需求，例如可按账号分配不同表的查询权限。 可以断开任意账号的连接。 |
| 普通账号 | 可以通过控制台、API或者SQL语句创建和管理。 一个实例可以创建多个普通账号 。 需要手动给普通账号授予特定数据库的权限。 普通账号不能创建和管理其他账号，也不能断开其他账号的连接。 |

**注意事项**

支持在控制台创建多个高权限账号和普通账号，也可以通过SQL命令创建、管理普通账号。 如果您要迁移本地数据库到RDS，请在RDS实例中创建与本地数据库一致的迁移账号和数据库。 分配数据库账号权限时，请按最小权限原则和业务角色创建账号，并合理分配只读和读写权限。必要时可以把数据库账号和数据库拆分成更小粒度，使每个数据库账号只能访问其业务之内的数据。如果不需要数据库写入操作，请分配只读权限。 为保障数据库的安全，请将数据库账号的密码设置为强密码，并定期更换。

**创建高权限账号或普通账号**

1. 登录云数据库RDS控制台。
2. 在**实例列表**页面，定位到目标实例。
3. 单击目标实例ID或者单击实例右侧的**管理**，打开**基本信息**页面。
4. 在左侧导航栏中，单击**账号管理**。
5. 单击**创建账号**并设置如下参数。

| 参数 | 说明 |
|---|---|
| 数据库账号 | 长度为2~16个字符。 由小写字母、数字或下划线组成。 以字母开头，以字母或数字结尾。 |

| 账号类型 | PolarDB实例支持两种数据库账号：高权限账号和普通账号。 高权限账号拥有所有数据库的所有操作权限。 普通账号拥有已授权数据库（owner）的所有操作权限。 说明操作权限包括SELECT、INSERT、UPDATE、DELETE、TRUNCATE、 REFERENCES、TRIGGER |
|---|---|
| 新密码 | 长度为8~32个字符。 由大写字母、小写字母、数字、特殊字符中的任意三种组成。 特殊字符为!@#$%^&*() +-= _ |
| 确认密码 | 再次输入相同的密码。 |
| 备注 | 非必填。您可以在此处输入该实例相关说明，以减少后期沟通成本。最大支持输入 256个字符。 |

6. 单击**创建**。

### 设置透明数据加密TDE

RDS提供了透明数据加密TDE（Transparent Data Encryption）功能。TDE可对数据文件执行实时I/O加密和解密，数据在写入磁盘之前进行加密，从磁盘读入内存时进行解密。TDE不会增加数据文件的大小，开发人员无需更改任何应用程序，即可使用TDE功能。

**背景信息**

TDE通过在数据库层执行静止数据加密，阻止可能的攻击者绕过数据库直接从存储中读取敏感信息。经过数据库身份验证的应用和用户可以继续透明地访问应用数据（不需要更改应用代码或配置），而尝试读取表空间文件中的敏感数据的OS用户以及尝试读取磁盘或备份信息的不法之徒将不允许访问明文数据。 TDE加密使用的密钥由密钥管理服务（KMS）产生和管理，RDS不提供加密所需的密钥和证书。您不仅可以使用阿里云自动生成的密钥，也可以使用自带的密钥材料生成数据密钥，然后授权RDS使用。

**注意事项**

TDE开通后无法关闭。 仅支持在创建RDS实例的过程中开启TDE。 开通TDE后，如果是I/O密集型（I/O bound）场景，可能会对数据库性能产生一定影响。 使用已有自定义密钥时，需要注意： 禁用密钥、设置密钥删除计划或者删除密钥材料都会造成密钥不可用。 撤销授权关系后，重启RDS实例会导致RDS实例不可用。 需要使用主账号或者具有AliyunSTSAssumeRoleAccess权限的账号。

更多关于创建实例页面的信息，请参见创建实例。

### CloudDBA简介

CloudDBA是一种基于机器学习和专家经验实现数据库自感知、自修复、自优化、自运维及自安全的云服务，帮助用户消除数据库管理的复杂性及人工操作引发的服务故障，有效保障数据库服务的稳定、安全及高效。

**实例基础信息概览**

| 模块 | 指标项 | 说明与运维建议 |
|---|---|---|
| Serve r信息 | 版本/运行时间 | 显示数据库内核版本（如 8.0.36 ）及实例累计运行时间（Uptime）。用于确认环境一致性及实例稳定性。 |
| 连接信息 | 连接数上限/当前连接数/活跃连接数 | 格式示例： 1200 / - / 3 。 连接数上限：实例允许的最大连接数。 当前连接数：当前已建立的TCP连接总数。 活跃连接数：当前正在执行SQL的连接数。 说明若“当前连接数”接近上限，需警惕连接风暴；若“活跃连接数”远小于“当前连接数”，可能存在大量空闲连接占用资源。 |
| Buffer Pool | 总页数/空闲页比例/ 脏页比例 | 展示InnoDB缓冲池状态。 空闲页比例：反映内存剩余空间。 脏页比例：反映待刷盘数据量。比例过高可能影响刷盘效率，导致IO抖动。 |

**吞吐量、负载与深层引擎指标**

| 分类 | 指标名称 | 详细说明 | 运维分析与建议 |
|---|---|---|---|
| 吞吐量 | QPS \| TPS | QPS：平均每秒SQL语句执行次数。 TPS：平均每秒事务数。 | 趋势分析：突增通常对应业务高峰。 异常排查：若QPS/TPS下降但CPU升高，通常存在锁等待或慢SQL阻塞。 |
| DML分布 | DML执行次数 | select：SELECT语句每秒执行次数。 insert：INSERT语句每秒执行次数。 update：UPDATE语句每秒执行次数。 delete：DELETE语句每秒执行次数。 | 业务画像：识别业务是读多写少还是写多读少，辅助制定索引优化策略（如读写分离架构调整）。 |
| 连接会话 | 连接数 | 活跃连接数：已打开连接中处于活跃状态的数量。 总连接数：已打开连接的总数量。 | 瓶颈定位：关注活跃连接数的波峰。若活跃连接数长时间维持高位，需检查是否有长事务或未释放的应用连接。 |

| 缓存效率 | InnoDB缓存 | 缓存命中率：从内存读取数据的比例。 缓存使用率：Buffer Pool的占用比例。 | 性能关键：命中率应接近100%。低命中率意味着大量请求穿透到磁盘（物理读），导致性能急剧下降。需考虑增大Buffer Pool或优化 SQL。 |
|---|---|---|---|
| 数据访问 | InnoDB访问行数 | rows read：每秒读取的InnoDB _ 行数。 rows inserted：每秒插入的 _ InnoDB行数。 rows updated：每秒更新的 _ InnoDB行数。 rows deleted：每秒删除的 _ InnoDB行数。 | 索引优化：若 rows read 极高但返回结果 _ 集很小，说明存在全表扫描，急需添加合适索引。 |
| IO读写 | 逻辑读/物理读 | 逻辑读：每秒逻辑读次数（从 Buffer Pool读取）。 物理读：每秒物理读次数（从磁盘读取）。 | IO瓶颈：物理读激增是性能杀手，通常由冷数据访问、Buffer Pool不足或缺少索引引起。 |
| 锁竞争 | 行锁平均锁定时间 | 单位通常为毫秒（ms），反映获取锁的平均耗时。 | 并发冲突：数值越高，说明事务间争用越激烈，可能导致应用端超时报错。 |
| 锁等待 | InnoDB行锁等待 | InnoDB行锁平均等待次数：统计周期内行锁平均等待次数。 InnoDB行锁当前等待次数：当前时刻正在等待行锁的次数。 | 阻塞源头：若此曲线不为0，说明存在阻塞。需结合“会话管理”功能查找阻塞源头（Blocker） 并终止异常会话。 |
| 临时资源 | 临时表、文件 | 临时表：创建临时表的数量。 临时文件：创建临时文件的数量。 | SQL优化：频繁创建磁盘临时文件会严重拖慢 SQL速度。通常是因为 sort buffer size 不足或缺少索引导 _ _ 致无法利用索引排序。 |
| 异常监控 | 慢查询 | 慢查询：两个相邻采集点间新增的慢查询数量差值（即该时间段内的慢查询增量）。 | 根因关联：慢查询突增往往是CPU飙升、响应变慢的直接原因。需立即抓取慢日志进行分析。 |
| 网络带宽 | 网络流量 | 总流量/流入流量/流出流量。 | 带宽限制：若流出流量打满实例带宽，会导致连接超时或丢包；若流入流量异常，需排查大字段写入或潜在攻击。 |

### RDS PolarDB JDBC

**前提条件**

**背景信息**

JDBC（Java Database Connectivity）为Java应用程序提供了访问数据库的编程接口。PolarDB实例的 JDBC是基于开源的PostgreSQL JDBC开发而来，使用PostgreSQL本地网络协议进行通信，允许Java程序使用标准的、独立于数据库的Java代码连接数据库。 JDBC驱动程序使用了PostgreSQL 3.0协议，与Java 6（JDBC 4.0）、Java 7（JDBC4.1）和Java 8（JDBC4.2）兼容。

**下载JDBC**

JDBC驱动阿里云提供了兼容Java 6、Java 7和Java 8三个Java版本的JDBC驱动，对应三个Jar包，包名分别为 `polardb-jdbc16.jar` 、 `polardb-jdbc17.jar` 和 `polardb-jdbc18.jar` 。您可根据应用使用的 JDK版本选择合适的JDBC。

**配置JDBC**

在Java应用中使用JDBC前，需要将JDBC驱动包的路径添加至 `CLASSPATH` 中。例如您的JDBC驱动放置的路径为/usr/local/polardb/share/java/，在 `CLASSPATH` 中添加JDBC驱动路径的命令如下：

```
export CLASSPATH=$CLASSPATH:/usr/local/polardb/share/java/<安装的Jar包名.jar>
```

示例：

```
export CLASSPATH=$CLASSPATH:/usr/local/polardb/share/java/polardb-jdbc18.jar
```

您可以通过如下命令查看当前使用的JDBC版本： `java -jar <`安装的`Jar`包名`.jar>` 示例：

```
java -jar polardb-jdbc18.jar
```

返回示例：

```
POLARDB JDBC Driver 42.2.5.2.0
```

**前提条件**

**背景信息**

PolarDB .NET（全称为ADO.NET Data Provider for PolarDB）是使用C#、Visual Basic、F#等语言访问PolarDB的驱动，驱动提供了对Entity Framework Core和Entity Framework 6.x的兼容能力，您可以使用本驱动结合Entity Framework快速开发应用程序。 当前的驱动程序使用了PostgreSQL 3.0版本协议，与.NETFramework 4.x、.NET Core 2.x兼容。

**Entity Framework简介**

Entity Framework是.NET平台上流行的ORM框架。在使用C#编写后端应用时，Entity Framework以及 LINQ技术极大地加速了后端应用的开发。 PolarDB .NET驱动提供了PolarDB的EF5、EF6的dll，用于使用Entity Framework。 关于Entity Framework的更多介绍，请参见Entity Framework官网。

2. 解压.NET驱动。

unzip polardb_oracle_.net.zip

**分区表Before Row-level触发器**

当您跨分区更新数据时，PostgreSQL和Oracle会使用不同的触发器行为： PostgreSQL：会触发多个分区表的触发器。 Oracle：仅触发一次触发器。 PolarDB O引擎默认兼容Oracle的触发器行为。 语句级触发器（Statement-level Trigger）与普通表用法相同。

**说明**

`polar_compatible_oracle_trigger = off` 表示PolarDB O引擎使用PostgreSQL的触发器行为，跨分区更新数据会触发多个表的触发器。

```
SET polar_compatible_oracle_trigger = off;
```

使用示例如下：

```
create trigger t before insert or update or delete on parted
  for each row execute function trigger_function();
insert into parted values (1, 1, 'uno uno v1'); NOTICE: parted_1: BEFORE ROW INSERT update parted set a = 2; NOTICE: parted_1: BEFORE ROW UPDATE NOTICE: parted_1: BEFORE ROW DELETE NOTICE: parted_2: BEFORE ROW INSERT delete from parted; NOTICE: parted_2: BEFORE ROW DELETE
```

`polar_compatible_oracle_trigger = on` 表示PolarDB O引擎使用Oracle的触发器行为，跨分区更新数据仅触发一次。

```
SET polar_compatible_oracle_trigger = on;
```

使用示例如下：

```
insert into parted values (1, 1, 'uno uno v1'); NOTICE: parted_1: BEFORE ROW INSERT update parted set a = 2; NOTICE: parted_1: BEFORE ROW UPDATE delete from parted; NOTICE: parted_2: BEFORE ROW DELETE
```
