### 管理转发路由器

#### 创建和管理转发路由器

一个地域支持创建一个转发路由器实例。转发路由器实例作为地域内的核心转发网元，帮助您转发同地域的流量。

**背景信息**

云企业网实例是转发路由器实例的载体，因此创建转发路由器实例前，您需要先创建一个云企业网实例，然一个云企业网实例管理一张网络，要互通的网络实例需连接至同一个云企业网的转发路由器上。支持创建多

**前提条件**

**创建转发路由器实例**

1. 登录云企业网管理控制台。
2. 在顶部菜单栏，选择云企业网实例的地域。
3. 在左侧导航栏，选择**云企业网实例**。
4. 在**云企业网实例**页面，找到目标实例，单击**云企业网****ID/****名称**列实例ID。
5. 在**云企业网实例详情**页面，选择**基本信息**页签。
6. 单击**基本信息**区域下方**创建转发路由器**。
7. 在**创建转发路由器**页面，根据以下信息配置转发路由器，然后单击**提交**。

| 配置项 | 说明 |
|---|---|
| 组织 | 选择转发路由器实例所属的组织。 |
| 资源集 | 选择转发路由器实例所属的资源集。 |
| 地域 | 选择转发路由器实例所属的地域。 |
| 版本 | 选择转发路由器实例的版本。当前仅支持选择企业版。 |
| 名称 | 输入转发路由器实例的名称。 名称长度为2~128个字符，必须以字母或中文开头，可包含数字、半角句号（.）、下划线（ ）和短划线（-），但不能以http://或https://开头。 _ |
| 描述 | 输入转发路由器实例的描述信息。 描述长度为2~256个字符，必须以字母或中文开头，但不能以http://或https://开头。 |
| TR地址段 | 输入转发路由器地址段。 单击添加，可以输入多个地址段。 单击 ，可以删除不需要的地址段。 TR地址段是您为转发路由器自定义的一组IP地址段，类似于路由器中为环回口 （Loopback接口）分配IP地址的地址段。TR的地址段不能和加入CEN中的任何网络地址段冲突。 这些地址段会被用作建立VPN attachment和Connect Attachment。VPN attachment己经被使用的地址段会自动的发布到同region的所有VBR中，请提前做好地址规划，避免云下路由被引流到云上造成非预期行为。 说明一个转发路由器最多支持配置5个地址段。每个转发路由器地址段的子网掩码位数不能少于16位，且不能超过24位。 不支持配置100.64.0.0/10、224.0.0.0/4、127.0.0.0/8、 169.254.0.0/16及其子网为转发路由器地址段。 每个转发路由器地址段不能与云企业网实例下所有待互通的网段冲突。 同一个云企业网实例下，每个转发路由器地址段需确保唯一。 |

##### 创建边界路由器实例连接

##### 创建云连接网连接

Connect连接是一种网络连接方式，用于在转发路由器与第三方设备（例如SD-WAN设备）之间建立连接。 Connect连接简化了企业本地网络的上云流程，可以帮助企业快速、高效地连接阿里云。

**背景信息**

**基本概念**

下表为您介绍Connect连接涉及到的一些基本概念。

**路由说明**

由于系统基于VBR连接在转发路由器和本地网络之间建立Connect连接，系统将在转发路由器下创建一个虚拟路由表（虚拟路由表不在控制台展示），虚拟路由表中汇总了当前地域下所有VBR实例学习到的本地网络的路由条目信息，转发路由器会通过查询虚拟路由表与本地网络建立网络隧道以及转发云上去往云下的流量。 对于云下去往云上的流量，在本地网络的流量进入物理专线后，系统将通过查询对应VBR实例的路由表以及如果转发路由器实例下存在多个VBR连接，且多个VBR实例学习到了相同的本地网络的路由条目，则虚拟路由表中将会存在多条目标网段相同，下一跳指向不同VBR连接的路由条目，这些路由条目会自动形成 ECMP（Equal-Cost Multipath Routing）链路。

**重要**

在转发路由器实例连接多个VBR实例的场景下（多条物理专线之间互为冗余）： 如果VBR实例和本地网络之间运行BGP动态路由协议，则在其中一条物理专线故障后，系统会自动将当前物理专线下Connect连接的流量使用其他正常的物理专线进行传输。 如果VBR实例和本地网络之间配置了静态路由，且您已在转发路由器管理控制台为VBR实例配置了健康检查，则在其中一条物理专线故障后，系统会自动将当前物理专线下Connect连接的流量使用其他正常的物理专线进行传输。 如果VBR实例和本地网络之间配置了静态路由，但您未在转发路由器管理控制台为VBR实例配置健康检查（不推荐），则在其中一条物理专线故障后，系统无感知，仍会向当前物理专线转发 Connect连接的流量，可能会影响您的业务。

**使用限制**

目前，Connect连接仅支持传输组播流量，不支持传输单播流量。 一个Connect连接下最多支持创建4个Connect Peer。 Connect连接不支持创建关联转发和路由学习关系。

##### 路由表

转发路由器支持创建自定义路由表。创建自定义路由表后，您可以为自定义路由表设置关联转发关系、设置路由学习关系、添加路由条目等，灵活控制网络实例的流量转发。

**背景信息**

转发路由器除包含一张默认路由表外，支持创建自定义路由表。转发路由器默认路由表和自定义路由表相互隔离，互不相通。默认路由表和自定义路由表说明如下： 默认路由表为系统自动创建。在您创建转发路由器实例时，系统自动为其生成一张默认路由表。 自定义路由表需要您手动创建。自定义路由表类比于传统路由器中配置的Virtual Routing Forwarding（VRF），与默认路由表及其他自定义路由表互不相通，可以实现访问隔离。 在您创建网络实例连接后，您可以通过设置关联转发关系将网络实例连接关联至自定义路由表，设置完成后，转发路由器将根据自定义路由表转发网络实例连接的流量。

##### 路由策略

###### 路由策略概述

转发路由器TR（Transit Router）支持路由策略功能。路由策略支持过滤路由、修改路由属性，帮助您自定义云上网络互通能力。

**工作原理**

转发路由器是地域内路由表和路由策略的载体。路由策略通过关联至转发路由器的路由表对路由进行过滤， 路由策略只影响所关联路由表的路由传播。 路由策略支持在转发路由器的入地域网关（RegionIn）和出地域网关（RegionOut）两个方向分别配置路由策略，每条路由策略均是条件语句和执行语句的集合。路由策略按照优先级进行排列，优先级数字越小， 优先级越高。执行路由策略时，路由从优先级最高的路由策略开始匹配条件语句，对于符合全部匹配条件的路由，路由策略将按照策略行为允许路由通过或拒绝路由通过，允许通过的路由支持修改路由的优先级、AS PATH属性、Community属性；对于不符合全部匹配条件的路由，系统默认允许路由通过。

**默认路由策略**

系统默认会在转发路由器路由表的出地域网关方向添加策略优先级为5000、策略行为为拒绝的路由策略， 该条路由策略会限制VBR与转发路由器下的其它VBR的互通能力。转发路由器下VPC、VBR之间的默认互通能力如下： VPC与转发路由器下的其他VPC、VBR互通。 VBR与转发路由器下的其他VBR不互通。

**组成部分**

路由策略包含策略基本信息、匹配条件和策略值三个组成部分。

**匹配流程**

路由策略采用match-action模式，即先匹配条件后执行动作。执行路由策略时，从优先级最高的路由策略开始匹配条件语句。 如果被匹配的路由满足路由策略中的所有匹配条件，则判断策略行为。 策略行为是允许：执行该路由策略中的执行语句并允许通过被匹配的路由。被匹配的路由默认不会再继续匹配下一条路由策略，但如果配置了关联优先级，被匹配的路由则需要继续匹配关联优先级的路由策略，如果未配置关联优先级，则匹配过程直接结束。 策略行为是拒绝：拒绝通过被匹配的路由，被匹配的路由默认不会再继续匹配下一条路由策略，匹配过程立即结束。 如果被匹配的路由与路由策略中任意一个匹配条件不匹配，则当前路由策略匹配过程直接结束，被匹配的路由继续匹配下一条路由策略。 如果被匹配的路由满足下一条路由策略中的所有匹配条件，则判断策略行为。 策略行为是允许：执行该路由策略中的执行语句并允许通过被匹配的路由。被匹配的路由默认不会再继续匹配下一条路由策略，但如果配置了关联优先级，被匹配的路由则需要继续匹配关联优先级的路由策略，如果未配置关联优先级，则匹配过程直接结束。 策略行为是拒绝：拒绝通过被匹配的路由，被匹配的路由默认不会再继续匹配下一条路由策略，匹配过程立即结束。 如果被匹配的路由与下一条路由策略中任意一个匹配条件不匹配，则当前路由策略匹配过程直接结束，被匹配的路由继续匹配再下一条路由策略。以此类推。 如果被匹配的路由匹配至最后一条路由策略，仍与该路由策略中的其中一个匹配条件不匹配，则允许通过被匹配的路由。

#### 组播管理

##### 组播概述

转发路由器支持组播通信。转发路由器连接网络实例后，可以帮助您创建和管理组播网络，并作为组播路由器帮助您转发网络实例间的组播流量。本文为您介绍转发路由器组播功能原理、使用限制和使用流程。

**背景信息**

**什么是组播**

组播是一种网络通信模式，通常应用于一个服务器同时向一组客户端（点对多点）发送相同数据报文的网络通信场景。例如在线直播、视频会议、金融交易行情数据同步、远程教育和网络电视等。

**组播的优势**

在点对多点的网络通信场景中，相对于单播和广播通信模式，组播通信模式可以帮助您减轻服务器负载并提高带宽的利用率。 以在线直播场景为例，为您介绍单播和组播通信模式的区别，方便您理解组播通信模式的优势。

**说明**

广播和组播通信模式的区别，请您自行查阅文档。 单播通信模式在单播通信模式下，视频直播服务器向客户端3和客户端4推送视频流量时，需要发送两份单播报文即单播报文1和单播报文2，由路由器将这两份单播报文转发至对应客户端。如下图所示。 组播通信模式在组播通信模式下，视频直播服务器和视频接收客户端加入同一个组播组中。视频直播服务器向客户端3 和客户端4推送视频流量时，只需要向组播组发送一份组播报文即组播报文1。该报文经过组播路由器转发，在靠近客户端的组播路由器上进行复制，组播报文被复制的数量依据组播组中的客户端数量决定。复制完成后，组播路由器将所有组播报文转发至对应的客户端。如下图所示。 对比以上两种通信模式，在单播通信模式下，服务器需要为每一个客户端单独发送一份单播报文，同时路由器也需要转发所有的单播报文。在客户端数量较多的情况下会增加服务器负载，同时会占用路由器较多带宽。而在组播通信模式下，视频直播服务器和视频接收客户端加入同一个组播组后，视频直播服务器只需要发送一份组播报文，在传输过程中，组播路由器也只需要转发一份组播报文，在转发组播报文过程中，只需要依据客户端的位置，在客户端临近的组播路由器上复制转发组播报文即可。在客户端数量较多情况下，组播通信模式可以有效减轻服务器负载，节省路由器的带宽。

您需要创建组播域来划分一个组播网络范围。仅在组播网络范围内的资源才能发送和接收组播流量。 具体操作，请参见创建组播域。

## 健康检查

边界路由器VBR（Virtual Border Router）实例通过物理专线连接本地数据中心。在将VBR实例连接至转发路由器实例后，您可以通过健康检查功能探测物理专线的连通性。

**背景信息**

**工作原理**

在您为VBR实例配置健康检查后，阿里云默认每隔2秒从每个健康检查源IP地址向本地数据中心的健康检查目标IP地址发送一个ping报文，如果ping报文从被探测物理专线链路**原路返回**，则认为物理专线链路正常。 如果某条物理专线上连续8个ping报文都**无响应或者****ping****报文从其他路径被返回**，则说明该物理专线链路故障。

**警告**

健康检查目标IP地址必须保证能正常回应ping的探测，本地数据中心不能对ping探测进行限速或者禁止ping探测。 如果本地数据中心网络设备配置了控制面板策略CoPP（Control Plane Policing）（如思科设备）或者本机防攻击策略（如华为设备）可能会导致健康探测报文被丢弃，造成健康检查链路震荡，建议本地数据中心网络设备取消CoPP限速配置。

**冗余物理专线说明**

对于本地数据中心通过多个物理专线连接至阿里云的场景，推荐您为每个VBR实例配置健康检查。如果健康检查探测到物理专线链路故障，系统默认会将当前物理专线的流量切换至其他任意一个正常的物理专线进行传输。 在您配置健康检查时，您也可以通过健康检查的**切换路由**功能自定义是否允许路由切换。

**前提条件**

您已经将物理专线关联的VBR实例连接至转发路由器实例。具体操作，请参见创建边界路由器实例连接。

**常见问题**

**在转发路由器连接多个VBR实例的场景下，物理专线之间互为冗余是基于什么粒**

**度的？**

物理专线之间互为冗余是基于路由条目粒度的。 例如转发路由器连接了VBR1和VBR2，转发路由器路由表下存在如下的三条路由条目： 当VBR1的健康检查失败时，VBR1下访问192.168.1.0/24网段的流量会被切换至VBR2下的物理专线进行传输。 当VBR2的健康检查失败时，VBR2下访问192.168.1.0/24网段的流量会被切换至VBR1下的物理专线进行传输，VBR2下访问192.168.2.0/24网段的流量不会被切换传输路径。

| 目标网段 | 下一跳 | 下一跳关联的网络实例 |
|---|---|---|

| 192.168.1.0/24 | VBR1连接 | VBR1 |
|---|---|---|
| 192.168.1.0/24 | VBR2连接 | VBR2 |
| 192.168.2.0/24 | VBR2连接 | VBR2 |

**在转发路由器连接多个VBR实例的场景下（物理专线之间互为冗余），如果所有**

**VBR实例的健康检查均失败，是否会导致流量中断？**

从阿里云去往本地数据中心的流量，阿里云侧默认通过最后一个VBR实例下的物理专线进行传输。 如果最后一个VBR实例健康检查失败，但是物理专线连通性实际是正常的，则会导致阿里云去往本地数据中心流量可用带宽减少（即只能通过一条物理专线进行传输）。 如果最后一个VBR实例健康检查失败，物理专线故障，则会导致阿里云去往本地数据中心的流量中断。 最后一个VBR实例是指健康检查最后失败的VBR实例。例如转发路由器连接了VBR1、VBR2和VBR3，转发路由器路由表中存在以下3条路由条目，系统先检测到VBR1和VBR2的健康检查失败，最后检测到 VBR3的健康检查失败，则VBR3即为最后一个VBR实例，阿里云去往本地数据中的流量均会通过VBR3下的物理专线进行传输。

| 目标网段 | 下一跳 | 下一跳关联的网络实例 |
|---|---|---|
| 192.168.1.0/24 | VBR1连接 | VBR1 |
| 192.168.1.0/24 | VBR2连接 | VBR2 |

**在转发路由器连接多个VBR实例的场景下（物理专线之间互为冗余），如果所有**

**VBR实例的健康检查均失败，是否会发生路由切换？**

路由切换的动作取决于物理专线连通性的变化，当健康检查探测到物理专线由连通变为不通，或者由不通变为连通时才会触发路由切换。

**删除健康检查配置，是否会导致路由动荡或者流量中断？**

如果您在转发路由器管理控制台删除了健康检查配置，不会导致路由动荡。系统会默认当前物理专线正常，并依据路由向当前物理专线转发流量。 如果当前物理专线实际处于故障状态，则会导致流量中断。 如果您在本地数据中心删除了健康检查配置，请根据您的网络配置自行评估。

## 操作日志

查看云企业网实例的操作日志，通过查看操作日志，可以了解实例运行的状态、操作来源、操作时间、API 调用详情等信息，便于对历史操作进行分析和回溯。

**操作步骤**

1. 登录云企业网管理控制台。
2. 在顶部菜单栏，选择云企业网实例的地域。
3. 通过以下两种方式查看实例的操作日志。
在导航栏直接查看操作日志。 a. 在左侧导航栏，选择**操作日志**。 b. 在**操作日志**页面，查看操作事件列表内容，包括**操作时间**、**操作人**、**资源类型**、**操作****IP**、**操作名** 称、**读写类型**、**操作结果**、**调用来源**、**组织**、**资源集**等。 单击**高级筛选，**支持按如下过滤条件进一步筛查出所需关注的操作事件。

| 过滤条件 | 说明 |
|---|---|
| 资源类型 | 选择资源类型，包括云企业网实例。 |
| 事件类型 | 根据资源类型选择事件类型，包括删除事件、创建事件、查询事件、修改事件。 |
| 起止时间 | 选择需要查看的时间范围。默认为当前月份。 |
| 资源ID | 输入资源类型实例ID。 |
| 操作IP | 输入操作IP。 |
| 读写类型 | 选择读操作或写操作。 |
| 操作结果 | 选择成功或失败。 |
| 关键词 | 输入关键词。支持事件ID、资源ID、源IP、操作名称检索。 |

单击目标操作事件**操作**列的**查看**，在**操作详情**面板，可以查看**基本信息**以及**实例详情**。 在实例详情页查看操作日志。 c. 在**云企业网详情**页面，单击**操作日志**页签，查看对应实例的操作日志。 操作事件内容包括**操作时间**、**操作人**、**执行状态**、**操作来源**、**操作类型**、**操作源****IP**、**操作时间**等。

当前操作日志保存时长为7天，如需调整，需管理员在配置-日志转存配置中操作配置。 若通过转存设置延长保存时长，日志数据不会做前序时间数据补充。 列表组件限制100页码，页面仅可展示10000条以内数据，超过10000条的数据可通过筛选方式按需展示。 单击**高级筛选**，支持通过**操作名称**、**操作人**等过滤条件组合筛选进一步选出所需关注的操作记录。

| 操作名称 | 选择目标实例的变更操作名称，即API名称。 |
| 执行状态 | 选择执行状态为成功或失败。 |
| 操作源IP | 输入操作源IP。 |
