### 阿里云域名解析DNS系统介绍

**DB管理系统**

DB管理系统通过基线中相应的版本号和数据库中记录的版本号进行比较，实现对数据库版本的管理，保障每次升级部署操作中数据库版本的正确性。

**API系统**

API系统实现所有调用的业务逻辑判断，全量数据管理和任务管理的功能职责，系统编写语言为JAVA。

**DNS解析系统**

DNS解析系统包括BIND和Agent两部分，Agent负责接收和处理API系统的任务信息并将任务解析成指令下发到BIND系统中。

### 例行维护

#### 查看运行日志

在运维过程中，如果因排查故障需要对日志进行查看，可根据不同系统的对应路径下的日志文件进行相应的查询操作。 API日志：运行日志文件路径主要在/home/admin/gdns/logs/下，可以根据实际需要对该文件进行查询。 Agent日志：运行日志部署在DNS服务的/var/log/dns/下，日志按天进行轮转。 BIND日志：运行日志部署在DNS服务器上的/var/named/chroot/var/log/下。

#### 服务启停

API启停，通过admin用户登录到API服务器后运行 `/home/admin/gdns/bin/appctl.sh restart` 可重启 API服务，建议分台执行，保障一台停止时有一台能正常提供服务，该脚本接受**start**，**stop**，**restart**三个参数。 DNS服务启动，服务通过Anycast IP提供服务，在停止应用前应当先通过 `service ospfd stop` 将 OSPF路由摘除，保障流量不再进入后，通过 `service named stop` 将DNS服务停掉。 DNS的停止，应当遵循先启动DNS再启动OSPF的步骤，执行命令分别为： `service named`

```
start ， service ospfd start 。
```

Agent服务启动，直接通过 `/usr/local/AgentService/agent -s start` 即可将应用启动，如果遇到提示PID文件已经存在，请先手动删除 `/var/dns/dns.pid` 文件再执行本命令。 Agent服务停止，直接通过 `/usr/local/AgentService/agent -s stop` 即可将应用停止。

#### 数据备份

服务升级如果需要备份数据，请将/var/named/目录/etc/named/目录备份至备份处，还原时将数据拷回原地址即可，但此间不能触发自动升级流程，否则会导致数据出现不一致的可能。

### 日志分析

**根据RequestID**

前端调用者发过来的请求之后，会收到API返回信息，返回信息中会包括RequestId。RequestId的使用方式如下：
1. 在数据库中查询task，可以查询到RequestId.
2. 在API系统的日志中同样可以通过RequestId查询日志中关于当前请求的执行结果或者异常信息。
3. 在 `bindServerRole#` 中同样可以根据RequestId查询日志中当前记录的结果，并联合各个系统中的信
息对结果进行验证。
