### 查看服务配置参数

服务配置分为全库配置和单库配置，分别控制全局配置参数和针对单个数据库的配置参数。本文介绍主要参数的详细说明。

| 配置项 | 描述 | 建议配置 |
|---|---|---|
| 审计选项 | 用于控制系统对受保护数据库的审计动作。 全审计：记录全部的数据库行为。 满足规则审计：只记录触发了规则的数据库行为。 | 建议开启全审计。 |
| 结果集审计开关 | 用于指定系统对SQL结果集的审计动作。 开启：解析并记录SQL结果集。 关闭：不记录SQL结果集。 | 建议关闭或在单库参数配置处开启。 全部开启结果集会消耗系统处理性能，且占用磁盘空间。 |
| 结果集最大保存长度 | 用于控制系统保存SQL结果集的最大数据长度， 范围是1~1024K。 | 建议保持默认值1K。 非必要情况下，结果集越少，性能损耗越小。 |
| 结果集最多保存行数 | 用于控制系统保存SQL结果集的最大行数，范围是1~2,147,483,647。 | 建议保持默认值3行。 非必要情况下，结果集越少，性能损耗越小。 |
| 用户名解析开关 | 用于控制是否对SQL Server数据库和客户端加密传送的用户信息进行解析。 开启：解析加密的用户信息。 关闭：不解析加密的用户信息。 | 根据实际需要配置。 |

### 审计类故障

#### 完全不审计

本文介绍审计页面无法检索到数据的可能原因和解决方案。

**问题描述**

审计页面无法检索到数据。

**可能原因**

RMAagent没有连接到系统。 RMAgent连接状态异常。 应用和数据库同一台主机，RMAgent没有配置抓取回环包。 RMAgent部署到Windows服务器上，应用和数据库同一台主机，服务器没有安装npcap。
**审计方式**为**满足规则审计**，且没有命中规则。

**排查思路**

1. 登录Apsara Uni-manager运营控制台。
2. 在控制台顶部菜单栏，单击**安全**，选择**数据安全**＞**数据库审计**。
3. 在需要登录数据库审计系统的**操作**栏，单击**详情**，登录到数据库审计系统。
4. 在左侧导航栏，选择**配置**＞**RMAgent****组件**。
5. 在**RMAgent****组件**页签，进行如下检测：
i. 检查是否有目标主机的RMAgent。 如果没有，则代表当前RMAgent未连接至系统，请登录RMAgent所在主机系统。检查如下相关项： a. 检查RMAgent进程是否正常启动。 Windows系统通过查看任务管理器检查RMAgent进程状态，Linux系统通过 ps -ef|grep `rmagent` 检查RMAgent进程状态。 b. 检查RMAgent配置文件rmagent.ini中配置的主机IP是否为审计系统IP。 a. 通过ping方法检查RMAgent所在主机是否能够和审计系统网络联通 b. 通过 `nc -nvv` 命令或telnet命令检查RMAgent所在主机是否能够和审计系统的9266端口联通，如果无法联通，请检查客户侧是否有防火墙限制了9266端口。 如果以上检查有一项未通过，可以确认问题是由于RMAgent部署后未能正常连接系统导致，请参考该步骤解决问题。 查 ii. 检查目标主机的RMagent是否正常。 有可能出现以下3种异常状态： 目标RMAgent显示异常：有可能是RMagent所在的数据库服务器宕机、或者RMAgent服务在运行后又停止导致。 目标RMAgent超限挂起：RMAgent宿主机CPU/内存或RMAgent自身占用CPU/内存超过限制触发了挂起机制。 RMAgent版本不匹配：RMAgent版本和审计系统版本不匹配。 如果出现以上任意一种，请参考该步骤解决问题。 iii. 如果应用或测试客户端和数据库服务器在一台机器上，则流量走本地回环网卡（loopback网卡），如果不确定流量是否在同一台机器，可以通过执行以下命令确认（以数据库端口为9207端口为例，请改成实际端口）： Linux系统，执行netstat -nap|grep 9207 Windows系统，指定netstat -nao|findstr 1433

**说明**

如果应用和数据库在同一台主机上，且两者之间交互将使用回环网卡，需要RMAgent开启支持回环网卡的功能。 `loopback=1` 为开启，如果配置中没有开启或加注释，说明问题由此导致。请参考该步骤解决问题。 查 iv. 如果经过上一步排查RMAgent配置了loopback没有问题，需要检查操作系统上是否安装了Npcap工具。请在控制面板检查是否安装了Npcap。 Npcap支持抓取回环的流量，如果没有安装，说明问题由此导致，请参考该步骤解决问题。 v. 如果系统设置了满足规则审计，没有配置针对执行的SQL规则，且没有触发规则。用户可以在**维护**＞引
**擎管理**页面，检查配置。
如上图所示，审计选项配置了**满足规则审计**，说明问题由此导致，请参考该步骤解决问题。

**解决方案**

1. 如果RMAgent进程没有存在，请手动启动RMAgent。
如果rmagent.ini中的server_ip非审计系统IP，请手动改为正确的IP后重启RMAgent。 如果RMAgent所在主机和审计系统网络不通，请客户侧网络工程师解决网络问题。 如果RMAgent所在主机到审计系统的9266端口不通，请客户侧网络工程师在中间防火墙中开放端口。
2. 如果显示状态为**异常**，请数据库侧运维人员排查主机。如无异常，可登录数据库服务器启动RMAgent服
务。 如果显示状态为**挂起**，检查RMAgent宿主机当前CPU、内存使用率。 如果占用率过高，请客户技术人员适当减轻压力。 如果宿主机整体CPU\内存很高，确保有足够可用空间，也可以调整RMAgent触发超限的参数。请使用 secadmin账号登录系统。在**配置**＞**RMAgent****组件**＞**RMAgent****管理**页面，选择目标RMAgent，单击**配置**，修改参数**cpu_limit/my_cpu_limit/mem_limit/my_mem_limit**。 查如果RMAgent版本过低，请在下载最新的RMAgent在目标主机安装。
3. 请使用secadmin账号登录系统，在**配置**＞**RMAgent****组件**＞**RMAgent****管理**页面，选择目标
RMAgent，单击**配置**，修改参数**loopback**为 1 。
4. Windows数据库服务器安装Npcap软件（可通过重装RMAgent时选择Npcap附带安装），如果已安装
Winpcap，需要先卸载Npcap再安装Winpcap。
5. 在**维护**＞**引擎管理**＞**审计选项**页面，修改**审计选项**为**全部审计**。

#### 语句漏审

本文介绍部分语句无法检索到的可能原因和解决方案。

**可能原因**

设置了信任规则，并且命中信任规则。 会话、SQL超限。 审计的oracle数据库可能开启了动态端口功能。

**排查思路**

对某类操作、客户端IP、数据库用户等设置了信任规则，所以不审计，请检查是否有此类规则。 查如果规则内容正好跟漏审的语句对应，请参照解决方法1解决问题。 设备型号所支持的会话、数据库流量过大超出规格型号限制后，新会话和语句将不会审计。请在系统页面点击告警，检查是否有SQL超限和会话超限的告警。 查询用户的oracle数据库版本是否为9i、10.1版本，数据库服务器是否为Windows版本。

**解决方案**

1. 调整规则。
ii. 在控制台顶部菜单栏，单击**安全**，选择**数据安全**＞**数据库审计**。 iii. 在需要登录数据库审计系统的**操作**栏，单击**详情**，登录到数据库审计系统。 iv. 在左侧导航栏，选择**规则**＞**规则管理**。 v. 定位到目标规则，单击操作列的图标，调整对应规则。
2. 对比规格型号，减少受保护数据库数量或者购买更高型号设备。
3. 添加受保护数据库处勾选动态端口选项。

#### 审计不到用户名及客户端信息

**可能原因**

数据库类型不支持审计用户名和数据库客户端信息现场的会话是长连接登录过程中有丢包没有开启SQL Server用户名解析功能 SQL Server添加受保护数据库填写的数据库用户权限不足或没有配置用户 SQL Server的会话是超短连接系统管理口和SQL Server网络不通或大量丢包

**排查思路**

查
1. 系统虽然支持对多种数据库进行审计，但是不是所有的数据库，都支持审计到全部的信息，例如客户端信
息。排查此问题时，需先确认被保护数据库的类型是否支持审计用户和其他客户端信息，可参照解决方法 1解决问题。
2. 数据库用户名、客户端工具、主机名、OS用户等信息，通常只有在客户端与数据库建立连接时传送，而
建立连接后的过程中，只会发送SQL语句，不会传送上述信息。所以，如果系统收到的流量都是不含连接信息的流量，则无法审计到用户名等信息。一般情况下以下3种情况可能导致没有审计到建立连接的信息： 系统接入客户网络时，数据库连接已建立，导致没办法获取连接数据库。 审计的过程中，重启过实例，导致无法识别重启前的连接信息。 插件部署场景下，在登录数据库过程中，插件工作有过短暂中断，导致转发到系统的包不含登录信息。 如果发生或会话超限，新会话被丢弃（可查看系统告警）。 插件部署模式下，插件由于网络压力大，发生过丢包（可查看RMAgent日志）。 上述前三种情况为外界因素，需要抓包排查短时间内是否有建立连接的数据包。抓取网卡的流量。过滤目标数据库，定位到目标语句所在会话，检查是否有建立数据库连接的包。不同数据库建立连接的数据包内容不同，需要去了解不同数据库的机制，下面仅以Oracle和MySQL为例下面讲解了能审计到基本信息的包是什么样： Oracle Request,Connect包是客户端登录数据库的第一个建立请求包，下方的Request,Data User OCI Functions则包含了数据库用户名、主机名等基本登录信息。 MySQL MySQL的Login Request包中包含了登录的用户名查如果通过以上排查方法，排查到没有建立会话的信息，可能为外界因素导致，在下次重新连接后即可正常。如果原因4-5，是请参照解决方法2解决问题。
3. 如果是SQL Server数据库，由于客户端与数据库交互过程中过程中，加密传输用户名和客户端信息，所
以需要检查是否开启了用户名解析的功能。使用secadmin账号登录系统，在**维护**＞**引擎管理**页面，检查**用户名解析开关**是否为关闭。 如果关闭，请参照解决方法3解决问题。
4. 如果是SQL Server数据库，且确保开关已开启，需要检查在在配置数据库时，是否配置了有获取权限的
用户。在**配置**＞**数据库**页面，检查SQL Server的配置信息，确认是否配置了用户名和密码。如果配置， 单击**权限校验**查看此用户是否有权限。
5. 如果是SQL Server数据库，由于获取用户名等信息需要系统连接数据库获取，所以如果连接时间很短，
系统还来不及获取这些信息，会导致审计不到用户名和工具等信息。在单库中单击**会话**＞**会话检索**页面， 查看会话的登陆时间和离开时间。 如果如上图所示，会话持续时间不超过30s，即由于超短会话导致的问题，请参考该方案解决问题。
6. 登录系统后台，使用ping命令测试管理口和SQL Server数据库的连通性。如果网络不通或有丢包，请参
考该方案解决问题。

**解决方案**

查
1. 针对数据库是否支持，可参考用户手册或咨询支持人员。
2. 如果是会话超限导致的问题，需要核对现场实际流量是否就是为会话过大，实际流量大，可考虑升级型
号；如果是RMAgent压力过大导致丢包，可参见解决办法。
3. 试用secadmin账户登录系统，在**维护**＞**引擎管理**页面，修改**用户名解析开关**为开启。
4. 联系DBA赋予此用户更高权限或者在添加数据库窗口配置sa用户。
5. 让会话持续时间大于1分钟。
6. 请网络工程时调整网络，使管理IP与数据库IP网络连通。

#### 审计到影响行数或响应时间为0

**可能原因**

单个包的大小超过RMAgent默认转发能力导致丢包单个包的大小超过RMAgent默认缓冲区空间导致丢包

**排查思路**

由于此现象的直接引发原因为结果集丢包，所以需要进行抓包，然后定位到目标语句的响应包去分析。 如果排查时发现，目标语句的响应包（结果集）出现如上图所示情况，则代表语句的响应包发生丢包，针对丢包，有如下几种可能的原因，请逐一排查： 在插件部署的模式下，如果原始包大小大于rmagent所能获取的长度，rmagent转发的包则也是丢失的。请通过抓包中观测丢失包的长度，如果大于8192，请参照解决方法1解决问题。 在插件部署模式下，如果原始包太大，而rmagent收包缓冲区大小不够大，则rmagent转发的包也可能丢失。请观察rmagent的info日志，如果在工作过程中，pcap drop字段有数目，则代表收包缓冲区空间不够，发生丢弃。

**解决方法**

修改rmagent的ini文件，调整目标RMagent的参数“pcap_snap_len”的值（可依据实际长度调整，也可调整为最大值），并重启RMagent。 修改rmagent的ini文件，调整目标RMagent的参数“pcap_buffer”的值（可依据实际长度调整，也可调整为最大值），并重启RMagent。

### 规则类故障

#### 没有触发规则

本文介绍规则触发失败的可能原因和解决方案。 查

**可能原因**

数据库配置了两个类似的规则： 规则A：针对select操作触发规则。 规则B：针对select操作大于20行触发规则，且一个优先级大于另一个。 查

**排查思路**

规则A的优先级大于规则B，导致在操作select查询语句的时候只触发了规则A，没有触发规则B。

## 常用工具指导

### tcpdump抓包

使用tcpdump工具捕获流量是排查流量问题时最常用的操作。本文介绍tcpdump的常用参数。 常用参数： -s ：从每个报文中截取一定字节的数据，为防止包被截断，建议设置其值为0，代表其可以截取最大范围 -i ：指定网卡，如果值为any，代表将捕获任何网卡的流量 -r ：从文件中读取流量而非网卡 and：设置过滤条件时，代表多个条件为“与”的关系，同时满足才满足 or：设置过滤条件时，代表多个条件为“或”的关系，任一满足即满足 host：过滤IP，如果不指定将捕获任何IP port：过滤端口，如果不指定将捕获全部端口 -w：把捕获结果存入文件 -n：解析域名，输出中显示IP而不是主机名配置示例： 捕获eth0网卡的流量：tcpdump -s 0 -i eth0 捕获bond0的流量，过滤主机192.168.XX.XX：tcpdump -s 0 -i bond0 host 192.168.XX.XX 捕获bond0的流量，过滤主机192.168.XX.XX和1521端口：tcpdump -s 0 -i bond0 host 192.168.XX.XX and port 1521 捕获bond0的流量，过滤主机192.168.XX.XX和192.168.XX.XX之间交互的流量： tcpdump -s 0 -i eth0 host 192.XX.XX and 192.168.XX.XX 捕获eth0的流量，过滤主机192.168.XX.XX或192.168.XX.XX的流量，并存入test.cap文件： tcpdump -s 0 -i eth0 host 192.168.XX.XX or 192.168.XX.XX -w test.cap 从capfie文件中读取流量，并且解析域名： tcpdump -s 0 -r /tmp/nfw4web_pcap_recv.fifo -n
