## 运维概述

### 系统架构

对象存储OSS是构建在阿里云飞天平台上的一种存储解决方案。其基础是飞天平台的分布式文件系统、分布式任务调度等基础设施。这些基础设施提供了OSS以及其他阿里云服务所需的分布式调度、高速网络、分布式存储等重要特性。 OSS的架构如下图所示： OSS的架构分为三层：协议接入层、分区层、持久存储层。 协议接入层 WS：Web Server网页服务器，使用的是开源的tengine组件，对外提供HTTP和HTTPS服务。 PM：ProtcolModule 协议模块将HTTP请求转换为后端KV或者其他模块的操作，并负责接收用户使用 RESTful协议发来的请求，进行安全认证。如果认证通过，用户的请求将被转发到Key-Value引擎继续处理；如果认证失败，直接返回错误信息给用户。 分区层对象存储系统的索引层，主要通过一个高扩展、高性能且强一致的Key-Value存储系统来管理海量数据的索引信息。对象的索引通过Range Partition方式管理，OSS将海量对象的索引信息根据负载分成不同的 Range Partition，不同的Range Partition会分配给各个分区服务器来进行管理，并提供超大规模的并发请求、自动负载均衡和垃圾回收。 索引系统主要分为KV Master和KV Server，采用LSM-Tree的方式构建。KV Master主要负责管理和调度分区；KV Server负责分区的索引及数据存储。 对象存储 OSS 持久储存层对外提供Paxos-based高可靠、高可用的EB级大规模分布式文件系统。元数据存储在Master上，各 Master之间采用分布式消息一致性协议（Paxos）来确保元数据的一致性，从而实现高效的文件分布式存储和访问，保证数据在系统中有冗余备份以及在软硬件错误发生以后的故障恢复。

### 部署架构

通过本文您可以了解OSS的部署架构。OSS的部署架构由AG分组、盘古master分组、独立前端机分组等部分组成。 OSS的部署架构如下图所示。 对象存储 OSS OSS的部署架构各部分说明请参见下表。

| 组件分组 | 描述 |
|---|---|
| AG分组 | 每个集群有1到多台AG，每个region有多个集群，其中某个集群的1台AG上会部署 Quota Master服务。 |
| 盘古master分组 | 只部署盘古master服务和supervisor。 |
| 独立前端机分组 | 只部署OSS server（带有Quota Agent）和Image server。 |
| 混部Server分组 | 混部各种主要服务，涵盖了访问层、存储层、异步任务等主要负载。 Quota Agent总是与OSS server同机部署，图中省略。 |
| MNS分组 | MNS是DRS 1.0中使用的消息组件。除了不会部署OSS server外，其他服务混部方式和server分组类似。 |

#### 集群/Bucket迁移管理

通过集群/Bucket迁移管理功能，运维人员可以将OSS 1.0的集群Bucket数据迁移到新的CDS-OSS集群， 为老集群下线做准备。

**警告**

**背景说明**

由于CDS-OSS版本在数据结构上相较于OSS 1.0发生了重大变更，导致存量OSS 1.0集群中的Bucket数据无法通过热升级方式直接迁移到CDS-OSS架构。 为支持用户从OSS 1.0平滑过渡到CDS-OSS架构，OSS赤骥推出了集群/Bucket迁移管理功能，提供安全、高效且可管控的迁移能力，助力业务实现架构演进与资源优化。

**注意事项**

对象存储 OSS 当前只支持OSS 1.0单集群或容灾单集群到CDS-OSS单集群的Bucket迁移，不支持对开启了跨云复制或跨域复制的Bucket进行迁移。 请确保Bucket未设置BYOK加密，且未同时配置保留策略（WORM）和日志（Logging）功能，否则将导致Bucket开启迁移时出错。 源集群和目标集群的**oss-server.OssServer#**以及**oss-chiji-agent.ChijiAgent#**对应的CPU架构必须相同，请联系阿里云技术支持协助确认。 请联系阿里云技术支持协助排查源集群服务端的HTTPS TLS版本。如果TLS版本小于1.2，请升级后再操作。 在容灾场景下，仅支持容灾环境到CDS-OSS单集群的迁移。开启迁移或者迁移Bucket过程中不能进行容灾切换。同时，需联系阿里云技术支持排查集群基础信息以及清理非预期的容灾同步配置。 开启迁移前，建议为存量Bucket配置生命周期规则，清理无用数据，减少资源浪费。 开启迁移后，建议不要新增或删除Bucket，以免影响数据迁移。

**前置检查**

开启迁移前，请完成如下事项检查：
**待迁移****OSS 1.0****集群要求**：集群处于终态且pangu、kv等组件均正常运行，存储容量水位正常以及VIP
流量水位正常。
**目标****CDS-OSS****集群要求**：集群处于终态，存储容量水位正常以及有充足容量存储待迁移OSS 1.0集群的
数据。
**确认****MNS****组件正常**：请联系阿里云技术支持协助处理。

**常见问题**

**迁移操作是否需要业务应用侧修改配置？**

业务侧无需修改配置。

**在迁移过程中，是否会对现有业务运行造成中断或访问异常等影响？**

数据的写入、查询均是原路径，业务侧无感知。不会导致业务中断或访问异常。

**如果在集群迁移过程中创建Bucket，数据会存储到哪个集群？**

数据会存储到目标CDS-OSS集群。

**Bucket级别迁移完成后，是否还能使用原OSS 1.0集群的Endpoint请求资**

**源？**

OSS 1.0集群的Endpoint会保留，且使用该Endpoint仍能访问迁移前写入的数据。

#### EC开关

对象存储 OSS 集群默认采用纠删码EC（Erasure Coding）来保障用户数据的可靠性和一致性，EC能提高存储可靠性。相比三副本技术而言，EC能够以更小的数据冗余度获得高数据可靠性。

**注意事项**

请勿随意关闭EC配置。关闭后会导致集群数据无法轮转为低备份比的数据，使集群容量上涨。 修改EC配置时，只支持修改为能获得更低冗余度的EC配置，系统会自动计算出符合更低冗余度的EC配置供选择。 修改集群 EC 配置方案后，系统会自动对集群内的数据发起 EC 变配，变配后新的数据将立即使用新的 EC配置，存量数据会异步转换为新的EC配置。

**配置EC模式**

集群默认已启用EC模式，可根据业务需求调整EC配置参数。

## OSS 5xx告警监控

在OSS的维护中，您可以获取包含5xx类型告警的日志，并通过日志信息对告警进行跟踪和分析。

**说明**

OSS集群升级、扩缩容过程中出现5xx告警一般为正常情况。用户的应用程序须具备重试机制。

**获取包含5xx告警的access_log日志信息**

您可以运行以下命令，从access_log末尾的10000行中获取最近的错误日志。

```
 tail -n 10000 /apsara/apache/logs/access_log.20150713 |grep "HTTP/1.1\" 5"
```

**说明**

如果未获取到需要的信息，可以扩大过滤的日志行数。 获取结果如下图所示。您可以在获取的结果中定位到包含5xx告警的request ID。

**根据request ID获取对应的fastcgi日志信息**

获取5xx告警的request ID后，您可以运行以下命令获取对应fastcgi日志信息，并根据这些信息做出相应的处理策略。

```
 grep $request_id /apsarapangu/disk1/logs/oss_server.LOG
```

## 安全维护

### 建立故障响应机制

在对OSS进行安全维护时，需要建立对故障的响应机制。 明确各类型故障责任人。 当OSS的监控出现告警时，应首先由驻场人员根据告警对问题进行排查。当驻场人员无法解决时，需要联系阿里云专有云服务团队。在生产过程当中遇到OSS产品相关的问题时，需要联系阿里云专有云服务团队。 建立备货机制。 为保证向用户提供高可靠的云存储服务，专有云 OSS 存储数据占用的磁盘空间不得超过OSS总容量的 70%。当超过OSS总存储容量的70%时，需要补充磁盘空间，使OSS的总可用空间大于50%。

### 日志审计

OSS会将用户的访问记录在日志中。在进行安全维护时，您可以通过日志对问题进行排查。 在专有云中，当有用户访问OSS存储的数据时，OSS会将用户的访问行为等信息记录在access_log中，并每天生成一个日志文件access_log.xxx（xxx 表示当天的日期）。当请求遇到问题时，您可以通过记录的日志对问题进行排查。您可以在 /opt/taobao/tengine/conf/nginx-proxy.conf 中配置日志的格式，格式如下：

```

                      '$status $body_bytes_sent $request_time_msec "$http_referer" '
                      '"$http_user_agent" "$host" "$upstream_http_x_oss_request_id" '
                      '"$upstream_http_x_oss_bucket_log_enable"
"$upstream_http_x_oss_requester" '
                      '"$upstream_http_x_oss_operation"
"$upstream_http_x_oss_bucket_name" '
                      '"$upstream_http_x_oss_object_name"
$upstream_http_x_oss_object_size '
                      '$upstream_http_x_oss_turn_around_time
"$upstream_http_x_oss_error_code" '
                      '$request_length "$upstream_http_x_oss_bucket_owner" '
                      '$upstream_http_x_oss_quota_delta_size
"$upstream_http_x_oss_sync_request" '
                      '"$upstream_http_x_oss_location"
"$upstream_http_x_oss_bucket_version" '
                      '"$vpcid" "$vpcaddr" "$upstream_http_x_oss_bucket_storage_type" $s
cheme "$upstream_http_x_oss_process _type"'
```
