# 混合云存储CDS EFS-NAS用户指南

阿里云弹性文件存储 EFS-NAS 用户

## 什么是EFS-NAS文件存储

**产品概述**

阿里云弹性文件存储 EFS-NAS（File Storage NAS）是面向阿里云ECS实例、E-HPC、容器服务等计算节点的文件存储服务。它是一种可共享访问、弹性扩展、高可靠以及高性能的分布式文件系统。EFS-NAS文件存储提供标准的文件访问协议，您无需对现有应用做任何修改，即可使用可共享访问、弹性扩展、高可靠以及高性能的分布式文件系统。

**产品类型**

EFS-NAS支持容量型和性能型两种实例类型，以满足不同的业务场景。 容量型实例基于SSD + HDD混合闪存服务器。 提供大容量、成本优化的共享文件存储方案。 适合档案管理、数据归档、视频监控回放等成本敏感场景。 性能型实例基于SSD全闪存服务器。 提供高吞吐、低延迟的文件访问能力。 适合高性能计算、媒体剪辑、数据库文件存储等性能敏感场景。

**核心功能**

文件系统挂载：支持多客户端挂载文件系统。 弹性扩容：可对文件系统进行在线扩容，随业务增长动态调整容量。 挂载点：支持通过NFS/SMB协议共享生成挂载点。 配额管理：支持按照组织设置容量配额，实现资源的合理分配、成本控制和性能优化。 单一命名空间容量：最大支持 5 PiB容量，实现海量数据统一管理。 单集群最大规模：支持最多 2000 块磁盘，按需横向扩展。 3 台起步部署：满足小规模业务起步与平滑扩容的需求。 存储池灵活部署：支持文件存储集群底层的资源独占与灵活规划，降低初期设备投入数量。 阿里云弹性文件存储 EFS-NAS 用户

## 使用须知

在使用EFS-NAS文件存储之前，您需要了解以下限制。

**文件系统限制**

单个文件系统最大文件数：100 亿。 单个文件的最大大小：512 TiB，推荐不超过 4 TiB。 最大目录深度：无限制，推荐不超过 20 级。 最大目录宽度：10 万。 单个文件系统容量范围：1 GiB～5 PiB。 单个文件系统最多能够被 2000 个客户端同时挂载访问。

**其他限制**

删除文件系统时，您需要在所有挂载该文件系统的客户端上执行卸载操作，再删除共享，最后删除创建的文件系统。 删除用户组时，需要先将用户组从SMB共享中移除；删除用户时，需要先将用户从用户组和SMB共享中移除。 阿里云弹性文件存储 EFS-NAS 用户

**方式二：进入ECS实例挂载/卸载文件系统**

**挂载文件系统**

**步骤一：安装NFS客户端**

将NFS文件系统挂载至云服务器ECS（Linux系统），您需要先安装NFS客户端。如果已安装NFS客户端， 请跳过此步骤。
1. 登录云服务器（Linux系统）。具体操作，请参见《**ECS****用户指南》**中的**快速入门** > **连接实例**章节。
2. 安装NFS客户端。
如果您使用CentOS、Red Hat、Aliyun Linux操作系统，请执行以下命令。

```bash
sudo yum install nfs-utils
```

如果您使用Ubuntu或Debian操作系统，请执行以下命令。

```bash
sudo apt-get update sudo apt-get install nfs-common
```

1. 登录云服务器ECS（Linux系统）。具体操作，请参见《**ECS****用户指南》**中的**快速入门** > **连接实例**章节。
2. 挂载NFS文件系统。
挂载命令可登录EFS-NAS控制台查看，具体步骤，请参照查看NFS共享信息。挂载命令示例： 使用NFS v4.1协议挂载文件系统：

```bash
sudo mount -t nfs -o vers=4.1,async,rsize=1048576,wsize=1048576 192.0.2.1:/efs-nasxxxxx /mount_point
```

使用NFS v4.0协议挂载文件系统：

```bash
sudo mount -t nfs -o vers=4.0,minorversion=0,rsize=1048576,wsize=1048576,hard,timeo=600,retrans=2,noresvpo 192.0.2.1:/efs-nas-xxxxx /mount_point
```

使用NFS v3协议挂载文件系统：

```
mount -t nfs -o vers=3,tcp,nolock,async,mountproto=tcp,rsize=1048576,wsize=1048576 192.0.2.1:/efs-nas-xxxxx /mount_point
```

### 文件系统配额

**背景信息**

EFS-NAS支持对文件系统设置配额，用于限制存储容量和文件数量，有效管理多用户场景下的存储资源分配，防止单个目录或用户占用过多存储资源。
**目录配额**：对指定目录设置配额，限制该目录的整体存储容量和文件数量。
**用户配额**：对指定用户在目录下的存储设置配额，限制该用户在该目录中可使用的存储空间和文件数量。

## 回收站

为避免误删文件系统中的文件导致业务受阻或数据永久丢失，建议您开启回收站功能。开启后，被删除的文件或目录将暂存在回收站中。并支持设置保留策略，被回收的文件在规定的保留时间到期之后彻底删除。您可以在保留期间恢复这些文件及其UID、GID和ACL等元数据信息。

**背景信息**

您在客户端上手动删除的 EFS-NAS 中的文件。例如手动执行 `rm -f test01.text` 命令删除文件test01.text，文件test01.text将进入回收站。 使用应用程序在客户端上自动删除的 EFS-NAS 中的文件或目录。例如Python使用 `os.remove("test02.text")` 删除文件test02.text，文件test02.text将进入回收站。 POSIX rename触发删除的文件或目录。例如同一目录存在文件test_a.txt和文件test_b.txt，执行 `mv` `test_a.txt test_b.txt` ，文件test_b.txt将进入回收站。 应用程序使用 EFS-NAS 文件系统产生的临时文件。例如执行**vim**命令编辑文件时，产生的 `.swp` 和 `.swpx` 格式的文件将进入回收站。 应用程序自动轮转的日志文件。例如使用Nginx配置了自动轮转日志且最多保留20个日志文件，当日志文件test.log.19轮转为日志文件test.log.20时，原日志文件test.log.20将进入回收站。

**说明**

如果仅覆写文件内容，不删除该文件，不会触发文件进入回收站。例如调用open()函数以w+模式打开文件并写入，原始文件不会进入回收站。

## 快照

通过快照可以定期备份文件系统的业务数据，以应对误操作、攻击或病毒导致的数据丢失风险。 为保障EFS-NAS文件系统中数据的完整性与可恢复能力，系统提供快照功能，用于创建某一时刻文件系统状态的只读副本。快照分为普通快照和定时快照两种类型，适用于不同的数据保护需求。两者的核心区别如下： 普通快照：由用户手动创建，适用于在系统升级、配置变更、数据迁移等关键操作前进行即时备份。 定时快照：由系统根据定时快照策略自动周期性生成，适用于生产环境中对重要目录进行日常备份，满足数据合规留存、防误删、自动化运维等长期防护需求。 建议结合实际业务场景，制定分层备份策略，实现安全性与资源成本的平衡。

### 创建快照

EFS-NAS产品支持普通快照和定时快照两种类型。普通快照由用户在需要时手动触发主动创建，定时快照由系统根据定时快照策略自动创建。本文介绍如何为文件系统创建快照。

**注意事项**

文件系统的路径层级不能超过16级，手动快照的路径长度不能超过4096，定时快照关联的路径长度不能超过4047。 单个文件系统推荐保留 128 个快照，最多创建 2048 个快照。所有文件系统最多创建 8192 个快照。 如果一个文件系统的快照还未创建完成，则无法为该文件系统再次创建快照，建议快照的创建时间间隔10 分钟以上。 快照只会备份某一时刻的数据，创建快照期间，操作文件系统产生的增量数据不会同步到快照中。 单个文件系统最多支持绑定8个定时快照策略。创建定时快照时，如果为单个文件系统多次绑定不同的定时快照策略，则这些定时快照策略会同时对该文件系统生效。

## WORM

WORM（Write Once Read Many）功能是用于保护文件数据安全的一写多读特性。启用 WORM 策略后，文件在指定保护周期内将受到严格访问控制，确保“一旦写入，不可篡改”，有效防范误操作、恶意删除或勒索攻击。

**核心价值**

防篡改、防删除在保护期内禁止人为误操作或恶意程序对关键文件的修改与清除，保障数据完整性。 满足合规要求支持金融、医疗、政务等行业对数据保留的强监管要求，实现审计可追溯。 自动化管理支持基于时间策略自动触发锁定与过期，无需人工干预，降低运维复杂度。 支持精细化控制可按文件系统级别配置不同保护周期，灵活适配多样业务需求。

**应用场景**

金融行业日志归档交易日志、审计记录等需长期保留且不可更改的数据，通过WORM实现合规存档。 医疗影像资料存储 PACS影像、电子病历等敏感信息，在法定保存期内禁止篡改，保障诊疗可信性。 企业法务与合同管理合同、知识产权文档等重要资料上传后自动进入保护状态，防止内部篡改风险。

### 创建WORM

文件系统启用WORM策略后，文件在写入完成时可手动设置或自动进入保护状态。在保护期间，文件仅允许读取，禁止修改与删除，确保数据完整性和不可篡改性，适用于合规归档、审计日志及长期数据保留等关键场景。

**注意事项**

目前仅支持合规模式，合规模式下任何用户不可删除和修改处于WORM保护期内的目录/文件。 基于合规考虑，文件系统启用WORM策略后，该文件系统的WORM不支持取消，且不可重复配置，请谨慎操作。
