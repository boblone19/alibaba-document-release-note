# 专有云部署服务 钟馗使用指南

## 钟馗使用指南

本文为您介绍钟馗抽检工具的背景、作用及流程。

**背景**

目前**专有云企业版新建**/**扩容**的**交付实施现场**，配置主要以标准机型的硬件基线为参考，在大量的轻资产场景下，配置情况不能得到有效的校准。而钟馗工具就是用来解决在轻资产场景下机型非标导致的IDC-Check阶段的卡点拥塞问题。

**整体流程**

在交付流程中，钟馗抽检工具作用于**硬件施工**阶段，在该阶段服务器已从厂商处出货，在机房到货上架，同时现场机房已经完成了**工勘**与**规划**，而又并未启动装机流程，在此阶段对服务器进行抽检，可以提前拦截服务器出厂配置错误并予以修正。

**工具介绍**

钟馗是一款由Python编写的**硬件固件配置检测工具**，作用为提前拦截服务器硬件固件参数配置错误，提升装机**IDC-CHECK**阶段时效。 钟馗镜像中已包含全部软件依赖，不需要在现场服务器中额外安装其他依赖。 钟馗镜像制作完成后可自动引导进入内存操作系统，不需要在现场服务器中预装操作系统。

**钟馗使用流程**

1. 获取钟馗镜像，参考下载钟馗安装包。
2. 制作U盘启动盘，参考U盘镜像制作指南。
3. 使用U盘对机器进行抽检，并将检查结果通过工单形式回传，参考机器抽检及数据回传分析。
4. 根据检查结果对现场机器进行改配，使其符合交付预期。

**解决问题**

装机问题在钟馗抽检阶段完成硬件非标问题拦截，减少专有云部署阶段卡点。 减少idc-check阶段配置非标的拉黑操作，避免为后续运维阶段埋雷。

**注意事项**

请现场在新建/扩容项目抽检之前，在**铜雀**平台检查是否有最新版本钟馗镜像，如有请根据最新镜像重新制作U盘启动盘。 针对**arm**与**x86**架构需使用不同的镜像。 结果文件idc-check-result.tgz必须是**gzip****格式**，否则可能会导致上传失败，可通过以下命令查询：

```
file idc-check-result.tgz
```

正确结果： 错误结果： 上架表中的机器可以不进行抽检，但抽检的机器SN必须在上架表中。 一个U盘可以多次使用，在不更新最新镜像的情况下不需要重复制作，当所需抽检机器较多时，现场可以根据需求多制作几个U盘，并行抽检，以提高效率。

## U盘镜像制作指南

本文为您介绍制作钟馗U盘镜像的详细流程。

**前期准备**

U盘建议U盘容量在16 GB及以上。 Rufus工具 Rufus工具官网下载地址：https://rufus.ie/，无特殊版本要求，下载最新版即可。 获取钟馗安装包镜像即zhong_kui_x86.iso / zhong_kui_arm.iso。

**操作步骤**

使用流程大致分为2步：
1. 制作U盘启动盘。
2. U盘装机，自动执行检查工具。

**制作U盘镜像**

1. 打开rufus软件，自动识别U盘设备，设备弹框显示U盘名称。
2. 选择引导类型。
单击**选择**，选择iso镜像（x86/arm架构需要分别选择对应的镜像）。
3. 其他配置按默认即可，单击**开始**，即可开始制作u盘，等待提示完成。
提示完成后，将U盘安全拔出，U盘镜像制作完成。

## 机器抽检及数据回传分析

本文为您介绍钟馗镜像制作完成后如何在客户现场使用，以及使用后如何处理结果的详细流程。

**前提条件**

已制作至少一个与目标抽检机器相同架构（**x86**/**Arm**）U盘钟馗镜像。 已获取到项目**服务器上架表**。

**操作步骤**

1. 抽检机器选择。
根据已获取到的**服务器上架表**进行人工判断，若某个**产品****(product)**的每个**serverRoleGroup**都部署了较多机器（单**serverRoleGroup**部署机器数量大于等于5台）时，建议每个**serverRoleGroup**抽取1～2台机器进行检查；若某个**产品****(product)**的每个**serverRoleGroup**部署的机器较少时，至少要求每个**产品****(product)**抽取1～2台进行检查。
2. 钟馗镜像抽检。
在抽检机器筛选完成后，可以使用之前制作的与目标抽检机器相同架构（**x86**/**Arm**）的U盘钟馗镜像， 插入目标抽检机器的**USB**口，随后**重启**该服务器（若服务器未上电则需要上电），钟馗镜像会自动进行抽检，并且抽检完毕后会自动关机，现场交付可以根据**服务器电源指示灯**亮灭判断抽检是否已完成。抽检完成后U盘可以继续抽检下一台目标机器，直至所有目标机器抽检完毕，现场交付可以提前制作多个U盘钟馗镜像并行抽检，以提高抽检效率。
3. 上传抽检数据。
在抽检全部完成后，现场交付需要提交**专有云交付工单**，将数据文件通过**工单群**反馈给交付**L2****值班人** 员，由值班人员对数据进行分析和结果反馈。数据文件包括： 抽检完成后，会自动在U盘内生成抽检结果文件idc-check-result.tgz，当使用多个U盘时需将每个U盘内的结果文件分别上传给**L2****值班人员**，不必将其合并为一个tgz压缩包。 项目**服务器上架表**，必须保证**上架表**内包含每一台**已抽检机器**（**上架表**内机器可以不进行抽检，但已抽检机器必须在上架表内）。 将局点专有云版本号告知**L2****值班人员**。
4. 修复机器配置。
在上传抽检数据之后，现场交付需要根据值班人员反馈对机器配置进行修复，当单台服务器出现问题时， 需注意所有**同批次机器**均需要进行检查/修复。例如，当抽检a**产品****(product)**中某台机器出现某BIOS配置需要修复时，所有a**产品****(product)**机器均需检查该项BIOS配置是否需要修复，在修复完全部待修复机器配置后，钟馗部署结束，后续可以进入正式**IDC-CHECK**阶段。
