```
ip:port )
```

自动化测试页面，单击**配置中心**。 进入到如下页面在该页面上传规划json文件/直接按产品添加用例，然后单击下一步。 南

**说明**

建议优先添加vpc-test-env用例，用来先进行环境可测性检查。 如上图所示，有三个TAB页，分别是三种类别的用例，每个TAB页的左边是未选中的用例，右边是已经选中的用例，**如有需要，可以重新选择，大部分情况下直接保存。**选完之后单击下方的**保存**，即可开始测试。

容器部署成功后，如果admin/atjok等用户密码不是默认密码，需要在JOK全局配置中修改对应的用户名密码。 南

**检查和执行**

1. 检查现场云产品是否都选中，界面中存在未选择的的产品和需要手动测试的产品，各自的处理方法

南 i. 初始化用例，如下图为单个用例初始化所示。 ii. 批量初始化用例：用例较多时，可以单击**批量初始化**，来批量初始化用例。
3. **开始。**
进入详情页面，单击**开始**，直到运行完成。 南在页面最底部，显示的是执行步骤、以及执行情况。 南
4. **详情界面说明。**
南 i. 执行步骤中的所需的参数，单击页面中**点击修改配置**可修改参数（可在弹窗右侧修改，但不可新增参数），页面**已知问题处理方法**中包含此CASE之前出现问题的处理方法。 南 ii. 可查看步骤所包含的groups，以及执行过程中的截图，方便问题定位，也可产看日志信息。 iii. 此处为步骤跳过操作和代码编辑位置，可以跳过无法测试的步骤，以及修改Web页面变动元素的 xpath。 南跳过步骤截图。 代码编辑截图，弹窗右侧编辑代码。

南 i. 用例执行完成后，需要清理执行时创建的资源，单击界面上的**清理资源**，进行资源操作。 ii. 清理完成后，此云产品CASE所有功能测试执行完成。 南 iii. 自动清理操作：如果需要CASE执行完成后，自动清理，需要打开**自动执行**开关。

**功能测试报告保存和处理**

1. **保存报告。**

**说明**

请在Windows电脑上使用chrome浏览器和Microsoft office word完成下面的操作，其他的环境未测试，如果有问题请联系阿里云技术支持。 i. 测试完成后，在JOK客户端界面上单击**查看报告**，会弹出一个对话框。 南 ii. 在对话框中单击产品即可跳转到该产品报告页面。 iii. 在页面里面可以浏览一下测试报告，在这个页面中，正常情况下是不存在**现场环境未部署该功能点**字样的，而且也不会有图片破损的情况，如果有，需要确认。 南 iv. 确定报告完整性之后，右键单击另存为，注意重命名和选择网页，保存到本地是一个html文件和对应的图片文件。 v. 将报告的html保存好之后，可以使用如下的方法生成word测试报告。
2. **生成****word****报告。**
i. 在windows电脑上用office word打开html文件。 南 ii. 在word中把文件另存为word文档。 iii. 此时看这个word文件的大小，会发现只有**几十****KB**，因为图片还没有内嵌到word文档中。 iv. 在word文档中，先**ctrl+A**全选整个文档,，然后单击左上角的文件。 南 v. 然后单击编辑指向文件的链接。 vi. 在弹出的窗口中,确保上面的所有图片都是被选中的（蓝色的），选中将图片保存在文档中，然后单击确定。 南 vii. 回到主界面,按**ctrl+s**保存，然后能看到word文档的大小变成了几M**到几十**M的大小，表示图片在 word文档中。

**说明**

现场可能产品部分功能未部署，根据实际情况自行优化word版测试报告。
3. **测试结果包。**
测试完成后，将结果包导出。

**资源清理**

**说明**

容器清理之前先保证以下操作已完成（保证现场已导出报告）。
1. **容器清理。**
i. 登录安装JOK工具的物理机上，使用 docker ps -a | grep pocDocker 得到jok测试容器的id。 ii. 使用 docker ps -a | grep perftest 得到perf测试容器的id。 南 iii. 使用 docker stop $id && docker rm $id 停止并删除 jok 和 perf 测试容器。 iv. 使用 `docker volume ls` 和 `docker volume rm pocDataVol pocStaticVol` 清理jok测试容器的数据卷。
2. **部门删除。**
如果使用ASCM，那么需要用运营管理员admin登录ASCM，然后删除创建的Jok相关用户、组织和资源集。
