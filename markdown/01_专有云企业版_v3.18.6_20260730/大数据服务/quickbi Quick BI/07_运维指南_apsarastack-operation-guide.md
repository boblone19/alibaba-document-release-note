# BI 运维指南

## 运维概述和工具

### 运维概述

Quick BI产品运维指南旨在指导运维工程师对Quick BI进行日常巡检、监控、维护及故障排查处理等操作， 确保系统的可用性、稳定性及安全性。 您可通过飞天基础运维平台系统来排查Quick BI不可用的问题。 您可通过大数据管家的赋能，专有云驻场人员可以轻松地管理大数据产品，例如，查看大数据产品的运行指标、修改大数据产品运行配置、查看并处理大数据产品的报警等。

### 通过大数据管家运维Quick BI

大数据管家支持从业务、服务、集群和主机等多个角度对大数据产品进行运维。除此以外，大数据管家还支持对大数据产品进行补丁升级、自定义大数据产品的报警上报配置、查看大数据管家中的运维操作历史等。 大数据管家ABM（Apsara Big Data Manager），原名BCC，是为大数据产品量身定做的运维管理平台。 大数据管家的登录方式及Quick BI相关的运维操作，请参见下方的《**Quick BI****运维》**章节。

### 缓存组件

本节介绍缓存组件的容器监控异常排查及巡检管理。

**容器监控**

查看飞天基础运维平台上的服务角色**quickbi-redis-master#**和**quickbi-redis-slave#**是否已达终态。 也可以查看redis进程。如果redis进程存在，则监控状态为已达终态。

**说明**

如果检测状态为非终态，则说明服务有异常。异常原因为redis进程中断或未启动。 处理措施：需要重启该服务角色。先重启**quickbi-redis-master#**，再重启**quickbi-redis-slave#**。

**巡检管理**

通过在容器中执行**/checkRedis.sh**命令来判断脚本的退出状态。如果退出状态为0，则服务正常，否则服务异常。脚本检测redis的服务进程是否存在，存在则退出状态为0，否则退出状态非0。检测间隔为一秒检测一次。

### Web服务组件

**容器监控**

查看飞天基础运维平台上的服务角色**base-biz-yunbi#**是否已达终态。 如果检测状态为非终态，则说明服务有异常。异常原因： Java进程中断或未启动。判断方法：http://container:7001/checkpreload.htm。 HTTPS证书未下发，443端口不通。判断方法：https://container/checkpreload.htm。

**说明**

**巡检管理**

周期性地调用HTTPS服务：https://container/checkpreload.htm。如果返回状态为200，则表示服务正常，否则服务异常。检查周期为五秒钟。 HTTPS服务链接中的container是一个变量，您需要用**base-biz-yunbi#**这个服务角色

**说明**

### QuickBI 服务运维

#### QuickBI 服务概览

服务概览界面展示集群中所有的 QuickBI 服务角色，及每个服务角色的 CPU、DISK、MEMORY、 LOAD、PACKAGE、TCP 和 DISK ROOT 使用趋势图。

**服务概览界面入口**

1. 在**运维**界面上方选择**服务运维**。
2. 在**服务运维**界面左侧的服务列表上方选择集群，然后再选择某个服务。
3. 在右侧选择**概览**，进入该服务的**概览**界面。
**概览**界面向您展示当前选中服务角色的 CPU、DISK、MEMORY、LOAD、PACKAGE、TCP 和 DISK
ROOT 使用趋势图。

**CPU**

按时间以不同颜色的曲线当前选中服务角色对 CPU 的使用率，包括 CPU 的总使用率（cpu）、系统对 CPU 的使用率（sys）和用户对 CPU 的使用率（user）。 单击图右上角的图标，放大 CPU 使用趋势图。 在放大图中，您可在左上方指定时间段来查看当前选中服务角色对 CPU 的使用率。

**DISK**

按时间以不同颜色的曲线展示当前选中服务角色对存储空间的使用率，包括 /、 /boot、/home/admin 和 /home 目录的存储空间使用率。 单击图右上角的图标，放大 DISK 使用趋势图。 在放大图中，您可在左上方指定时间段来查看当前选中服务角色对存储空间的使用率。

**LOAD**

按时间以不同颜色的曲线展示当前选中服务角色的一分钟、五分钟和十五分钟平均负载。 单击图右上角的图标，放大 LOAD 用趋势图。 在放大图中，您可在左上方指定时间段来查看当前选中服务角色的一分钟、五分钟和十五分钟平均负载。

**MEMORY**

按时间以不同颜色的曲线展示当前选中服务角色对内存的使用量，包括内存使用率（mem）、总内存大小 （total）、已使用的内存大小（used）、buff 使用的内存使用量（buff）、cache 使用的内存大小 （cach）和空闲内存大小（free）。 单击图右上角的图标，放大 MEMORY 使用趋势图。 在放大图中，您可在左上方指定时间段来查看当前选中服务角色对内存的使用量。

**PACKAGE**

按时间以不同颜色的曲线展示当前选中服务角色的数据传输情况，包括丢包数量（drop）、错误包数量 （error）、接收包数量（in）和发送包数量（out）。 单击图右上角的图标，放大 PACKAGE 趋势图。 在放大图中，您可在左上方指定时间段来查看当前选中服务角色的数据传输情况。

**TCP**

按时间以不同颜色的曲线展示当前选中服务角色的 TCP 协议的使用情况，包括主动打开的 TCP 连接数目 （active）、被动打开的 TCP 连接数目（pasive）、收到的 TCP 报文数目（iseg）、发出的 TCP 报文数目（outseg）。 单击图右上角的图标，放大 TCP 使用趋势图。 在放大图中，您可在左上方指定时间段来查看当前选中服务角色的 TCP 协议使用情况。

**DISK ROOT**

按时间以不同颜色的曲线展示当前选中服务角色对根盘的平均使用率（avg）。 单击图右上角的图标，放大根盘平均使用趋势图。 在放大图中，您可在左上方指定时间段来查看当前选中服务角色对根盘的平均使用率。

按时间以不同颜色的曲线展示集群的一分钟、五分钟和十五分钟系统平均负载。 单击图右上角的图标，放大LOAD使用趋势图。 在放大图中，您可在左上方指定时间段来查看集群的一分钟、五分钟和十五分钟系统平均负载。

#### QuickBI 集群健康

集群健康界面展示集群的所有检查项、检查项的详情（提供检查项报警的解决方案）、各检查项在宿主上的检查状态，同时还支持直接登录宿主以及手动对宿主执行检查项检查。

**集群健康入口**

1. 在**运维**界面上方选择**集群运维**。
2. 在**集群运维**界面左侧的导航树中选择某个集群，然后在右侧选择**健康**，进入该集群的**健康**界面。

**查看监控项详情**

1. 在集群**健康**页签，单击目标监控项**操作**栏中的**详情**，在弹出的对话框中查看监控项详情。
监控项详情包括**名称**、**来源**、**别名**、**所属应用**、**类型**、**调度是否开启**、**系统默认参数列表**、**用户自定义参**
**数列表**和**描述**，其中描述中附有检查项报警的解决方案。
2. 单击下方的**显示更多**，查看监控项的更多信息。
监控项更多信息包括**执行脚本**、**执行目标**、**系统默认阈值判定**和**用户自定义阈值判定**。

**查看报警的宿主以及报警原因**

通过监控项的宿主，您可查看该监控项是对宿主的历史检查记录以及检查结果。
1. 在集群**健康**页签，单击存在报警的监控项前面的
图标，查看该监控项所有的**宿主**信息。
2. 单击**宿主**名，然后在弹出的对话框中单击某个报警后面的**详情**，可在右侧查看报警原因。

**处理监控项报警**

在集群**健康**页签，单击存在报警的监控项后面的**详情**，在**详情**弹窗中查看监控项报警的处理方法。

**再次检查**

处理完某个报警后，您可在集群**健康**页签，单击目标宿主后面的**操作** > **再次检查**，对该宿主进行一次该检查项的实时检查，以确定该宿主的报警是否恢复。

### QuickBI 主机运维

#### QuickBI 主机概览

主机概览汇总了 ElasticSearch 集群中主机的总体运行信息，包括该主机当前的根盘使用率、总使用率、 1/5/15 分钟负载、运行健康、运行健康历史记录，以及 CPU、DISK、MEMORY、LOAD、PACKAGE、 TCP 和 DISK ROOT 的使用趋势图。

**主机概览入口**

1. 在**运维**界面上方选择**主机运维**。
2. 在左侧**主机运维**界面左侧导航树中选择某个主机，然后在右侧选择**概览**，进入该主机的**概览**界面。
**概览**界面汇总了当前选中主机的根盘使用率、一分钟负载、总使用率、CPU、DISK、MEMORY、
LOAD、PACKAGE、TCP、DISK ROOT、运行健康和运行健康历史记录。

**CPU**

按时间以不同颜色的曲线展示该主机的CPU使用率（支持指定时间段），包括CPU的总使用率（cpu）、系统对CPU的使用率（sys）和用户对CPU的使用率（user）。 单击图右上角的图标，放大CPU使用趋势图。 在放大图中，您可在左上方指定时间段来查看该主机的CPU使用率。

**DISK**

按时间展示该主机的存储空间使用率，包括/目录下存储空间使用率。 单击图右上角的图标，放大DISK使用趋势图。 在放大图中，您可在左上方指定时间段来查看该主机的存储空间使用率。

**MEMORY**

按时间以不同颜色的曲线展示该主机的内存使用量，包括内存使用率（mem）、总内存大小（total）、已使用的内存大小（used）、buff使用的内存大小（buff）、Cache使用的内存大小（cach）和空闲内存大小（free）。 单击图右上角的图标，放大MEMORY使用趋势图。 在放大图中，您可在左上方指定时间段来查看该主机的内存使用量。

**LOAD**

按时间以不同颜色的曲线展示该主机的一分钟、五分钟和十五分钟系统平均负载。 单击图右上角的图标，放大LOAD使用趋势图。 在放大图中，您可在左上方指定时间段来查看该主机的一分钟、五分钟和十五分钟系统平均负载。

**PACKAGE**

按时间以不同颜色的曲线展示该主机的数据传输情况，包括丢包数量（drop）、错误包数量（error）、接收包数量（in）和发送包数量（out）。 单击图右上角的图标，放大PACKAGE趋势图。 在放大图中，您可在左上方指定时间段来查看该主机的数据传输情况。

**DISK ROOT**

按时间以不同颜色的曲线展示该主机的根目录（/）平均使用率。 单击图右上角的图标，放大根目录使用趋势图。 在放大图中，您可在左上方指定时间段来查看该主机的根目录平均使用率。

**运行健康**

统计该主机当前的巡检项总数量，以及该主机中的 CRITICAL、WARNING 和 EXCEPTION 的报警数量。

**运行健康历史记录**

简要的展示主机健康检查的历史记录。 单击每次检查的**事件内容**，查看此次检查的异常项。

#### QuickBI 主机健康

主机健康支持查看所有宿主（即主机）的检查项、检查项详情（提供检查项报警的解决方案）、各检查项的状态，同时还支持直接登录宿主以及手动对宿主执行检查项检查。

**主机概览入口**

1. 在**运维**界面上方选择**主机运维**。
2. 在左侧**主机运维**界面左侧导航树中选择某个主机，然后在右侧选择**健康**，进入该主机的**健康**界面。
**健康**界面显示当前主机的所有检查项及检查项状态。检查状态分为
**CRITICAL**、**WARNING**、**EXCEPTION**和**OK**，并分别以不同颜色显示。其中
**CRITICAL**、**WARNING**、**EXCEPTION**是报警事件，您需要重点关注，特别是
**CRITICAL**、**WARNING**报警事件。

**查看检查项详情**

1. 在主机健康界面，单击检查项后面的**详情**，在弹出的对话框中查看检查项详情。
检查项详情包括**名称**、**来源**、**别名**、**所属应用**、**类型**、**调度是否开启**、**数据收集是否开启**、**系统默认运行**
**间隔**和**描述**，其中描述中有附有检查项报警的解决方案。
2. 单击下方的**显示更多**，查看检查项的更多信息。
检查项更多信息包括**执行脚本**、**执行目标**、**系统默认阈值判定**和**数据收集挂载点**。

**查看报警原因**

通过检查项，您可查看该检查项是对宿主的检查记录以及检查结果。
1. 在主机健康界面，单击存在报警的检查项前面的**折叠**图标，查看该检查项的宿主。
2. 单击**宿主**，然后在弹出的对话框中单击某个报警后面的**详情**，在右侧查看报警原因。

**处理检查项报警**

在主机健康界面，单击存在报警的检查项后面的**详情**，在弹出的对话框中查看检查项报警的处理方法。

**登录宿主**

如果某个宿主有报警事件或其他情况，您可能需要登录到宿主进行相关操作。
1. 在集群健康界面，单击检查项前面的**折叠**图标。
2. 单击宿主后面的**登录**图标，打开**TerminalService**界面。
3. 在**TerminalService**左侧选择宿主，即可直接登录。

**再次检查**

处理完某个报警后，您可单击宿主后面的**再次检查**，对该宿主进行一次该检查项的实时检查，以确定该宿主的报警是否恢复。
