## 1 Product details

Key Management Service (KMS) provides customer master keys, Bring-Your-Own-Key (BYOK), key rotation, master key aliases, and resource tags.

**Customer master keys**

The key service is the core component of KMS. The encryption keys are called customer master keys (CMKs). CMKs include the following: Symmetric key: Used primarily for data encryption. If you do not specify a key specification (KeySpec), KMS creates a symmetric key by default. You can use the KMS encryption and decryption APIs to encrypt and decrypt data without exposing the plaintext key. Asymmetric key: Used primarily for data encryption and digital signatures. An asymmetric CMK that you create in KMS consists of a public and private key pair. The public key can be distributed to anyone, but the private key must be kept secure. KMS protects the private key and does not provide an API to export it. To use the private key for decryption or digital signatures, you must call the relevant cryptographic operation APIs. Anyone who has the public key can use it to encrypt data or verify a signature that was generated by the private key.

**Bring-Your-Own-Key (BYOK)**

To meet higher security and compliance requirements, KMS supports BYOK to protect your data in the cloud.

**Key rotation**

You can enhance key security using key versioning and periodic rotation. This helps you implement security policies and best practices for data protection. Key rotation can be automatic or manual. Automatic key rotation: KMS supports multiple key versions for a single CMK. Each version is an independent key and is not related to other versions. Based on this multi-version capability, KMS provides a built-in feature for automatic key rotation. This helps you implement security best practices and meet compliance audit requirements. Manual key rotation: If the key type you are using does not support automatic rotation based on key versions, you can manually rotate the CMK.

**Master key aliases**

KMS supports creating aliases for master keys. Aliases make it easier to identify and manage master keys. An alias is an optional identifier for a customer master key and must be unique within an organization and region. The same organization can use the same alias in different regions. In a single region, each alias can point to only one customer master key, but each customer master key can have multiple aliases.

**Resource tags**

Resource tags make it easier to manage key resources in KMS.

## 3 Benefits

Compared with traditional key management infrastructure (KMI), Key Management Service (KMS) offers multi-service integration and is easy to use.

**Multi-service integration**

KMS seamlessly integrates with multiple products, such as ECS, RDS, and OSS. This integration lets you easily use KMS master keys to encrypt and control the data stored in these services and manage your computing and storage environments in the cloud.

**Ease of use**

| Benefits | Description |
|---|---|
| Easy encryption | KMS simplifies cryptographic concepts by providing simple APIs for data encryption and decryption. For applications that require a key hierarchy, KMS provides a convenient envelope encryption feature to quickly implement the hierarchy. For example, you can generate a data key (DK) and use a master key (CMK) as a key encryption key (KEK) to protect the DK. |
| Centralized key hosting | Key Management Service provides centralized hosting and control of your keys. You can import keys to KMS from your on-premises key management infrastructure (KMI) . Whether keys are created in KMS or imported from external sources, the confidential or sensitive data in the keys is used by other Alibaba Cloud products for encryption. |
| Bring-Your-Own- Key (BYOK) | KMS supports Bring-Your-Own-Key (BYOK). You can import your own keys to KMS to encrypt data on the cloud. This gives you better control over key management. |
| Custom key rotation policies | KMS lets you automatically rotate symmetric encryption keys based on your security policies. Key rotation helps you achieve the following goals: Reduce the amount of data encrypted by a single key. Enable a faster response to security events. Logically isolate data. Reduce the time window for a key to be compromised. Meet compliance requirements. |

## 4 Scenarios

You can use Key Management Service (KMS) to encrypt and protect sensitive data in the cloud. For example, KMS enables application developers to protect the keys that are used to secure sensitive data in their applications.

**Envelope encryption**

With envelope encryption, you can store master keys in KMS and deploy only the encrypted data keys. When a data key is needed, you can call KMS to retrieve the plaintext data key. You can then use the plaintext key to encrypt and decrypt your business data.

**Direct encryption**

You can call the Encrypt or Decrypt API operations of KMS to directly encrypt or decrypt sensitive data with a master key.

**Server-side encryption**

You can use the server-side encryption feature of cloud products to simply and effectively protect your data. For example, you can enable server-side encryption for Object Storage Service (OSS) to protect buckets that store sensitive data, or use transparent data encryption (TDE) to protect tables that contain sensitive data.
